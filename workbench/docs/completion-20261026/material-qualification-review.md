## 实际范围

- 新增 `material-qualification-review/1` 关闭字段协议：固定 scope、seal、input、quote、job/execution profile、account、模型/serializer/judgment 摘要，复用现有整数价格政策；三类证据必须指向同一项目的确切原件版本与摘要；每条规则固定请求摘要、字节数与人工登记的 token 测量。测量值仍需真实证据，不能从合成值推导真实能力。
- `material_qualification` 可选 fresh-install SQL：不可变登记、不可变审核事件、具有同记录/同版本外键的审核头。未执行安装、未新增运行账户或凭据；未改变原生任务/预算/Worker 的角色、RPC 或触发器。
- API：在现有 technical-scope 路径增加 `POST material-qualifications`、`GET material-qualifications/{id}`、`POST .../{id}/decisions`。复用会话/CSRF、Command 幂等账本和审计；精确项目/包/修订/范围隔离，If-Match 冲突返回 412，原 key 原请求可恢复历史回执。历史回执不代表当前有效资格。
- 审核依据 DEC-016 的既有 active member 管理权限；没有另造人类管理员角色或外部权限。批准时再次检查当前模型方法、有效期和原件摘要；撤销为终态，漂移或过期后仍允许撤销。人工批准始终不授予准确性或执行资格。
- 已挂入现有完整材料界面：导入协议 JSON、登记、按确切编号读取证据、填写理由批准/撤销。发送前保存成员/范围隔离的原请求和 key；丢 ACK 后显式恢复；读取当前版本后才能再次审核；旧选择/旧成员的迟到响应不会污染界面。此阶段为运维审核入口，尚无证据自动采集器或表单生成器。
