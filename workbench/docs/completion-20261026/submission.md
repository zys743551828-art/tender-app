# 整包提交前原件复核阶段

日期：2026-10-26（北京时间）。本阶段完成公开复核接口、真实原件读取路径、界面动作、当前输入绑定与失败恢复边界。整包标准提交仍未取得完整放行依据，不能据本阶段把 F05-07 或全项目记为 100%。

## 解决的问题

原有 `submission-preview` 只读取数据库中的整包、清单、确认意见和历史风险；它正确显示“原件字节尚未核验”和“核查运行依赖尚未完成当前核验”。原件字节只在登记已经发生的线下提交事实时读取。用户缺少一个可以在登记前明确触发的原件复核动作。

本阶段增加 `POST /api/v1/bids/{bid_id}/packages/{package_id}/revisions/{revision_id}/submission-preflight`，并在现有整包提交表单的四类检查下提供“核验所选整包原件”。请求必须带精确的 `selection`、原预览 `input_digest`、当前强 `If-Match`，并通过会话与 CSRF 检查。

## 实际执行顺序

1. 在只读 REPEATABLE READ 事务中重新读取明确选择的投标包、依据包、要求清单、核查运行、逐项规则确认、全项目已知风险、当前实交头及来源状态。预览摘要或 ETag 不一致时，在对象读取前拒绝请求。
2. 读取精确核查运行原来的准备输入、事实依赖计划、所选事实准入和清单抽取凭据，使用原 scope-review admission 重新构造当前执行 manifest，逐项比较其摘要。未选运行、未成功运行及运行依据变化分别返回明确状态；不会获得模型客户端、创建模型请求或新任务。
3. 关闭数据库连接后，逐份读取投标包、依据包和来源祖先原件，按流核对声明字节数及 SHA-256。读取上限沿用最多 2,000 份原件，本次完整读取的合计声明大小上限为 8 GiB；超过容量拒绝整次复核，不截断文件列表。
4. 原件读取结束后重新认证当前账号，再建立新的只读数据库快照，重新读取全部上述依据。比较完整输入摘要、原件私有定位、运行依据、ETag、政策和门禁观察。即使来源只因时间经过而失效，数据库行和 ETag 未变化，也拒绝发布旧观察的成功回执。
5. 返回带摘要的 `package-submission-preflight/1` 回执。回执只公开原件身份、大小、摘要与角色，不包含对象定位、原件正文或数据库凭据。

原件检查通过并且核查运行的原执行依据仍匹配时，“当前输入与来源”这一门可以显示“此项已满足”。其他三类门继续保留各自的原始状态。回执中的 `allowed`、`inventory_complete`、`submission_eligible`、`publication_authorized` 和 `platform_submission_verified` 仍恒为 `false`。

## 界面与回执校验

界面校验回执的当前成员、项目、包修订、所选清单与运行、预览摘要和 ETag，重新计算回执摘要、完整所选包摘要和原件目录摘要。每一份目标或依据成员都必须在原件目录中出现；重复原件、越界角色、缺失成员、摘要替换、额外私有定位字段及重新签名的伪资格均被拒绝。

原预览中的身份、版本、来源等阻断不能借复核回执被删除或降级。仅原件尚未读取、运行依赖尚未检查这两个确实完成复核的原因可以消除。若自然生效等变化使旧预览无法证明新状态，界面要求重新读取预览。

切换成员或项目、重读提交检查、重试、会话失效会清除旧复核结果。请求代次和固定选择身份共同阻止旧请求晚到后填回新的界面。双击不会重复发起在途复核。失败不保留上一轮“已完成”的状态；线下事实登记继续使用原有保存前复查、原请求恢复与数据库守卫。

非 owner PG 用例包括：正确公开 API；投标与依据两份精确原件；字节损坏、对象不可用、来源撤回、项目变化；会话失效、账号更换；原预览摘要和 ETag 不符；原生对象定位的不可变守卫；来源在对象读取期间到期但数据库行和 ETag 不变；实际完成核查的原运行依据重新匹配以及撤回后的阻断。复核没有新增实际提交记录或提交命令，原测试核查的合成供应商调用数保持 1，没有因复核增加调用。

独立审查发现并关闭一项客户端缺陷：重新签名的回执可能删除原预览的身份阻断或将 blocked 降为 unknown/pass。已补保留原因、禁止 blocked 降级和两条反例；独立审查再次运行原反例，确认被拒绝。

首次 PG 运行有两条测试断言失败，原结果未当作通过：中间件将 `Cache-Control` 规范化为无空格形式；尝试改变原件定位被更早的 `append_only` 原生守卫拦住。修正断言并明确保留原生不可变测试后，12 项完整复验通过。首次默认沙箱纯路由运行在已有 asyncio/线程边界挂起；仅终止精确识别的本轮测试进程，相同组合在可运行的 host 测试环境通过。没有修改生产权限或关闭守卫以让测试通过。新增表单集成测试初跑的宽泛文案选择和异步表单就绪断言分别失败；改为定位复核区域、等待真实表单重新可见后，最终 53 项全部通过，未改业务逻辑迁就测试。

## 不授予的能力与后续条件

每份原件仅在本次读取时校验，随后数据库复查保证观察的一致性。这不构成 S3 与 PostgreSQL 的原子快照，也不是对象版本永不变化的保证，更不是可持久复用的提交许可证。实际登记仍然重新执行其原生检查和原件校验。

本阶段没有证明要求清单的语义完整性、真实核查质量、真实业务端到端效果或交易平台回执真实性；没有增加标准提交正向授权或把历史人工意见当作有效复检解决。`package-submission-gate/1`、原不可变提交绑定和 SQL 拒绝策略保持原语义。整包标准提交需要继续完成完整性及真实质量依据，不能用本次“原件已读”替代。
