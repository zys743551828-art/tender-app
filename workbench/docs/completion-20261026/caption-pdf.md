# 阶段二：实际 PDF 图注对应检查

承接已推送的 `80182d6521b6db71c81b61da9bed4c074aa06aa8`，接入独立 `rich_caption_pdf.inspect_captions`。生成/RICH 协议仍为 `/4`、`/5`，profile 新绑定图注检查器源码摘要；旧 profile 不能复用新检查资格。图片/表格检查与图注检查使用同调用的实际 PDF，不接收客户端提供的成功回执。

## 接受条件

- 枚举真实 named destinations，精确匹配冻结 `cap_` 锚点全集；重复、缺失、额外图注锚点或没有明确物理页/Y 坐标均拒绝。枚举使用 PDFium 的两次缓冲区调用，参照[官方 FPDF_GetNamedDest 接口](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/public/fpdfview.h)。
- 图片或原生表格必须先由原检查器完整测量。按冻结的各类型顺序绑定对象，不假定客户端节点 ID 跨章节全局唯一。
- 图注必须和对象同物理页、完整位于版心，在对象底部之后不超过48 pt。不允许其他正文或图表插入两者之间。缺少锚点时不回退为全文字符串搜索。
- 锚点附近须有唯一完整的图注行序列；NFC规范化后仅忽略排版空白，保留数字、大小写等字符身份。允许同页多行与多处相同文字；不允许同一个测量矩形被两个图注复用。
- 原生字形须为不透明黑色、非隐藏、无旋转/保留裁剪；使用同一实际 PDF 的独立文字层与白底合成，逐 RGB 像素对比实际页面，最大通道误差3。遮挡不因完整文本提取或大量空白而通过。该方法继承受控字体/源生成器边界，不证明任意恶意 PDF 字体映射可信。
- PDF 50MiB/1000页，named destinations最多2000、名称缓冲区最多2048字节，单图注最多100行，500万组合工作单位、6400万累计渲染像素；字符、对象、图形预算复用已绑定的表格检查器。最终强化把累计前缀和bbox扫描也计入组合预算。

证据仅含锚点/节点/节身份、物理页、矩形及文字摘要，不返回原始图注正文。失败或资源超限返回 partial。缺少原生对象证明时返回 `AUTHORING_CAPTION_OBJECT_UNVERIFIED`，其他图注不完整返回 `AUTHORING_CAPTION_PDF_UNVERIFIED`。顶层继续合并正文、字体、导航、表格等各自缺口。

## 实际验证与历史失败

新增23项真实合成 PDF 用例，另有1项 profile 摘要拒绝用例。图、表单行/多行/重复图注成功；缺失/重复/互换锚点、数字改变、白字、隐藏、黑白遮挡、太远、图表上方、异页、错误目的地、插入正文和三个资源预算均保持 partial。组合入口证明图注通过不消除缺少正文/导航的其他缺口。

首轮1 failed /21 passed：两个内容和几何完全相同的合成表格被既有表格检查器判为定位歧义。这是原接受域的正确拒绝；成功 fixture 改为表格内容可区分但图注相同，没有放宽表格检查器。导入格式及局部列表类型提示在静态检查中修正。

相关十文件 **192 passed /0 failed /0 skipped，3.78s**。完整默认回归 **3862 passed /0 failed /0 errors /2389 skipped，188.46s**。随后对累计前缀/bbox扫描计费的最后强化再跑同组 **192 passed，3.81s**；最后强化后的完整默认组由下一混排阶段再次执行，不把之前全量运行冒称为该行变更后的全量。完整 ruff/format（1077文件）、mypy（673源文件）、bandit 均通过。各组有重叠，不相加。

完整回归报告在 `.local/ci/caption-pdf/`。所有 PDF 均为明确合成字节；没有运行 Docker/LibreOffice、付费模型、生产库或原生 PG/Kafka/S3。未创建 PR/合并/部署。

## 明确未完成

此接受域是同页、非旋转、黑色文字、唯一可定位且紧随图表的图注。跨页图注、复杂Form/分栏、跨页表格和任意字体映射不获得资格；若实际转换不保留 `cap_` named destination，结果仍为 partial。新源协议与真实受控转换器的联合验收仍需固定Word03镜像来源和新受审profile，合成成功不能替代该条件。

图和表此前分别检查，仍不能证明相互混排顺序及表格所属节；下一阶段补齐这项明确代码缺口。
