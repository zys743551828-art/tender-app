# 完整材料申请与持久受阻回执

## 实际交付与入口

已保存技术范围及范围历史中增加“完整材料执行申请”。读取完整材料条件后，用户可固定材料封印编号/摘要、完整输入摘要、报价编号/摘要和预算，或全部留空核对缺失项。模型目标沿用仓库 DeepSeek / deepseek-flash 与完整图文 `/3` 配置；没有查询或宣称外部型号/能力已生效，没有换型号。

新增既有 technical-scope 路由下的：

- GET `material-execution-context`：复用当前技术范围、源效力及量尺资格检查，返回固定 profile/serializer/judgment 方法引用、ETag、缺口；execution_enabled 永远为 false。
- POST `material-execution-checks`：校验固定范围与方法、If-Match、Idempotency-Key 和封闭请求。在原有 `commands` 账本记录受阻回执，并写现有审计；不新增数据库表、任务、队列、预算或资格体系。200 只表示受阻检查结果已持久化，不表示执行获准。

原生材料读取/封印复验使用独立用途权限，公共 API 当前不能借这些权限访问。用户输入的 seal/quote 引用即使格式和摘要完整，也保持 `reference_status=unverified`；不读取其指向的原件、不认定它属于当前范围、不授予权威。当前拒绝发生在既有任务登记、预算预留、outbox 和发送入口之前，这些执行接口保持不变。旧文本 `/1` 检查独立保留，不自动成为完整图文方法。

## 幂等、恢复及陈旧证据

服务端先按原有 governance→bid→source 顺序取得范围状态，再使用既有 actor/kind/target/key 命令身份。重复同键同内容/同条件读取原回执，不新增命令效果；同键不同内容冲突。原回执可以在来源/方法变化后作为历史拒绝记录重放，不是当前资格。新申请必须匹配当前 scope/profile/serializer/judgment 与 ETag；陈旧条件返回412，未知费用或畸形引用返回422。正常拒绝同时保留原资格缺口、材料未复验、真实资格缺失、账户费用未核验三项固定阻断。

前端发送前保存按成员+范围+摘要隔离的 sessionStorage 原请求/ETag/操作键；存储失败不发送。丢ACK/网络失败保留原请求，只由用户明确恢复相同操作，不能伪造零效果回执；恢复响应严格核对 actor、scope、原请求摘要、方法引用、受阻标记和全部效应计数。切换成员/范围后忽略迟到响应。服务明确返回412时可由用户明确开始新的条件核对；无法确认的错误不能自动清除记录。已确认回执标出历史观察时间，重载后可恢复原回执，不自动执行任何请求。

API沿用登录、CSRF、原范围身份/项目校验；无请求中的actor、verified、grant或机制测试开关。审计只含范围和请求摘要，命令账本包含引用元数据，不包含原件、请求正文材料、凭据或租约token。没有新增权限。

## 仍未完成的正式条件

真实资格证据的提供主体、账户/模型/输入绑定、有效期、撤销及再核验语义仍未明确，不自定阈值或信任调用者布尔值。当前所有完整请求也会被阻止。因此本轮完成的是可用的固定申请/拒绝/恢复界面，不是正式任务接纳、发送或评分功能。

资格协议确定后，仍需将接受分支版本化接入已有原生登记、preflight、预算/一次发送/结算和Worker；不能将公共API的输入引用当作原生材料权威，也不能用旧文本方法或生成端口白名单替代完整图文方法。真实数据评测及正式预测资格仍独立未验收。
