# 阶段：原生表格的实际 PDF 几何与可见性检查

日期：2026-10-26（北京时间）。本记录描述软件检查器的交付范围，不表示 LibreOffice 转换、真实投标材料或 M1 双格式整体验收通过。

## 已完成

此前 RICH 只要含原生表格，就无条件返回 `AUTHORING_TABLE_PDF_GEOMETRY_UNVERIFIED`。现在 `rich_renderer.inspect_pdf` 调用独立的 `rich_table_pdf.inspect_tables`，根据实际 PDF 字节产生 `table_correspondence`。只有完整满足接受条件的表格才消除这个缺口；正文、图片、目录、字体、沙箱清理等其他缺口继续独立保留。

本阶段完成的接受域是：**同一物理页内、每条逻辑行边界可观察、具有完整不透明黑色直线网格的冻结原生表格**。支持普通单元格、横向合并、纵向合并，以及生成器的灰色表头底纹。PDF 中的描边或窄实心矩形都可以作为实际边框证据。

检查链如下：

1. 从已通过 `rich_renderer.prepare` 的冻结快照和真实 DOCX 原生表格取得列宽、网格占位、合并范围与各源单元格完整文本。段落、列表及列表数字由既有 OOXML 文字检查逻辑解析，不从 PDF 反推“应该有什么”。
2. 从实际 PDF 的原生路径读取横线、竖线和边框矩形；核对总宽、各列宽、完整边框、合并拓扑及四边版心范围。合并单元格内部出现额外分隔线不能通过。
3. 逐字符读取 PDF 字形矩形，要求每个字符完整位于唯一单元格的受检内部区域。逐格比较去除布局空白后的 NFC 文字，保留全部数字、大小写和兼容字符身份；不接受跨格、隐藏绘制、白字、透明文字、旋转文字或保留裁剪路径的文字。
4. 对每条预期边框检查实际页面栅格中的连续可见像素。再复制实际 PDF 页面并移除非文字绘制对象，得到独立原生文字图层；将它与预期的白色或固定灰色单元格背景合成，逐像素比较所有 RGB 通道。白色覆盖、黑色覆盖、一像素量级的窄覆盖、额外背景块不会因为全文提取相同而获得通过。
5. 每个冻结表格须有唯一完整匹配，顺序必须一致，不允许一张实际表格同时满足两张源表格。证据包含物理页、表格与单元格矩形、行列及合并跨度、文字摘要和字符计数，不返回或记录原始单元格正文。

## 资格与版本

- RICH 协议从 `authoring-rich-sandbox/3` 升为 `/4`。构建输入 manifest 直接引用 `rich_renderer.PROTOCOL`，避免声明与执行版本分离。
- 新 profile 绑定表格检查器源码摘要、PDFium Python 包版本、PDFium 引擎构建、Pillow 版本、接受域、位置容差、栅格比例和工作预算。旧 RICH profile 或重新散列但修改检查器/引擎身份的 profile 会在调用 Docker 前被拒绝。
- 未修改既有外部 Word03 或 PAGE 生成通道的源码摘要、基础沙箱准入、原件身份或转换限制。本阶段没有执行 Docker、LibreOffice、外部模型或生产环境写入。
- 独立文字层使用的是同一份实际 PDF 的原生字形与字体资源。它证明受控转换产物的格内排布及可见性，**不能证明任意不可信 PDF 的字体程序、ToUnicode 映射或业务语义正确**。正式调用仍须经过冻结源、受控生成器和精确 renderer profile 的完整链。

## 明确的部分覆盖条件

以下情况仍返回 `partial`，不转为完成资格：

- 表格跨物理页，或整行被纵向合并完全覆盖，无法在实际 PDF 观察该逻辑行边界；
- 缺边、缺列线、错误列宽、额外合并内分隔线、越出版心、文字跨单元格、文字内容/数字变化；
- 两处完全相同的候选导致定位歧义，源表格顺序颠倒，或同一实际矩形被多个源表格复用；
- 复杂 Form XObject、未知绘制对象、渐变、旋转页面等超出本接受域的图形；
- 隐藏、透明、裁剪或被覆盖的文字/边框；
- 任何独立资源限制或组合工作预算耗尽，或检查中断。

位置容差为 0.75 pt，连续线段拼接容差为 0.2 pt；单列及可观察行间距至少 4 pt，字形矩形必须离格边至少 1.5 pt。边框接受 0.25–1.5 pt 的不透明近黑色原生绘制。2 倍栅格下的单个边框采样像素上限 208 用于容纳细黑线在两个像素之间的抗锯齿分摊，并不授权隐藏边框或任意替代颜色；边框原生绘制身份仍先受检。单元格内部的独立文字层合成对比使用每个 RGB 通道最大差 3，不按空白面积稀释误差。

资源上限包括 50 MiB PDF、1000 页、500 张源表格、每页 20000 个原生对象/40000 个路径片段/200000 个字符、全稿 2000000 个字符、2000 次候选组合、6400 万累计栅格像素。另有 **500 万组合工作单位**：候选、网格边对路径扫描、逐字符对单元格扫描均在进入相应循环前扣预算。这防止多个单项均未超限时出现不可接受的乘积工作量。证据记录实际消耗的工作单位和栅格像素。

PDFium 的有效空 `CPDF_ClipPath` 在没有底层引用时返回路径数 `-1`；本检查仅在从有效实际文字对象取得非空 clip handle 时接受 `-1/0`，有保留路径的文字仍拒绝。该行为已用实际完整文字/部分裁剪文字 PDF 区分验证，并核对 [PDFium 官方实现](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/fpdfsdk/fpdf_transformpage.cpp) 与 [公开接口](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/public/fpdf_transformpage.h)。
