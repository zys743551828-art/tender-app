## 需求与语义

依据 `/workspace/tender-docs/02-业务与产品/一期方案与验证计划.md` 4.3、4.8、4.13：正式预测显示校准估计、约 80% 区间、训练组数和评估误差；失分点最多十条并可追溯原文。4.3 明确：“项目关闭‘显示预测分数’（`show_score`）时，报告与 Word 报告只列可能的失分点（条款、评估、正文证据），不出现估计值、区间与估计失分；预测照常进行，照样形成配对。”当前设置名为 `show_prediction`。隐藏是展示政策，不是删除内部预测或排除配对。没有为通过测试更改这条需求。

## 实际调用链

`PackageFormalPrediction` → `PackagePredictionReport` → 现有预测 command 下的 `GET /report` 或 `/report.docx` → `Reports` → 现有 `NativeTransactions.read/prepare` → `MaterialProjection` → 现有 `producer.consume`、`handoff.load` → 原 `assemble_report` Word writer → 再读权威 → 返回。

- 默认沿用既有预测服务配置，无独立配置、更无第二套模型/任务/证据仓库。未配置返回 503。
- 两次短事务之间做原件复验、确定性推断、引用投影和 Word 序列化；没有持锁读私有原件。认证、固定输入、模型、方法、展示设置变化即拒绝本次导出。
- 引文来自 `/3` 三槽原始响应，由原消费链验证原件字节、请求身份、原生页图与原文。附原文档/解析/物理页/页图摘要/文件摘要，可调用原有原页查看器；不是从模型自由文本伪造引用。
- 按条款满分减三槽档位均值排序，最多十条。这个档位观察差额不是 ridge 总分的可加分解；三次维度未一致支持只表示需要复核，不断言已经证明遗漏。当前投影不重新推导逐要点缺失或自动确认规则。
- Word 复用现有确定性 OOXML writer，控制字符按既有策略显示为 `[U+....]`。不解析源 XML、不嵌入脚本或外链，没有声称完成真实 Word→PDF。
- JSON 和 DOCX 均 `private, no-store`，直接新鲜生成，不发旧对象下载授权。刷新报告先隐藏页面旧数字；迟到响应不能挂到新的 scope。资格失败不会回落下载旧文件。

## 出口核对

| 出口 | 本阶段行为 | 边界 |
|---|---|---|
| 正式结果 API / UI | 沿用原读取复验；报告刷新时先清除旧数字展示 | 不主动撤回用户已经看到的数字 |
| 正式报告 JSON | 生成前后复验；隐藏时 score、条款满分/差额均 null | 原文中的数字仍是原件引文，不改写原件 |
| 正式预测 Word | 同一投影/复验；隐藏时不序列化估计/区间/误差/差额 | 已下载的字节无法远程撤回；只保证本次授权时刻 |
| 原页引用 | 原 Evidence/Document viewer 重新核对身份 | 不生成虚构位置 |
| 既有整包历史核查报告及 PDF | 其冻结协议本就声明非正式评分，本阶段未塞入新分数 | 新预测报告是同步配套报告，尚非四部分统一评审报告 |
| 旧单正文报告/批注 PDF | 仍使用原版本和原规则 | 不把 /3 偷换成旧 artifact |
| 度量配对 | 不修改上一阶段固定事前配对代码 | 隐藏不排除配对；真实配对未验收 |
| 通用任务/进度出口 | 本阶段未写入预测值 | 后续任务接线必须只暴露不含分数的任务回执 |

FR-007 原文要求四部分统一评审 Word。本阶段复用原 writer 交付可用正式预测配套报告，**没有把它冒充四部分统一报告完成**。后续在既有评审报告上下文中组合必须同时校验评审/预测固定输入，避免把不同 revision 的证据拼接。任务阶段亦尚未完成：Worker 不能拿 API 身份调用认证事务，应沿既有 operation/lease/outbox 计算、API 控制面复验发布，不新建队列框架。
