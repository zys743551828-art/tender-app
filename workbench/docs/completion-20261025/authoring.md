# 固定来源正文的显式人工文字修订

日期：2026-10-25。此增量落实 `docs/completion-20261021/exact-package-authoring-design.md` 中允许的“人工文字修订保留来源资格、另记人工修改”路径。它是可运行的后续编辑能力，不改变原 B3 模型候选采纳结论，也不把普通保存接口开放给固定来源正文。

## 已交付的使用路径

1. 在正文工作区选中含固定来源资格的章节。
2. 服务返回已安装且具有必要数据库权限的人工修订能力后，界面核对当前草稿快照、章节内容摘要、实际资格摘要和来源关联。
3. 点击“修改本章固定来源文字”，选择一个现有纯文字段落或标题，核对原文字，填写修改后的文字和修订说明。
4. 显式勾选确认后保存。服务验证旧基准和当前来源，核验真实对象存储原件，再次在事务中验证权限和全部基准，追加一个不可变章节修订、一份独立人工资格和新的草稿快照。
5. 可以继续对新修订执行同一人工修改流程，或使用既有构建入口生成 Word。实际 Worker 从真实 S3 原件检查及保存快照生成 DOCX；没有调用额外模型。

普通正文自动保存、章节目录修改、导入和富内容变更继续遵循原来的保护规则。人工修订仅改变一个已有段落或标题的文本，不允许请求携带或重写 `source_refs`、`rule_ids`、章节元信息、节点身份或格式。

## 身份、数据与恢复边界

| 层次 | 实现和验收边界 |
| --- | --- |
| API | `GET /api/v1/authoring/exact-text-edit-capabilities`；`POST /api/v1/bids/{bid_id}/authoring/drafts/{draft_id}/exact-text-edits`；既有资格查询可返回原候选资格或人工资格 |
| 人工资格 | 新协议 `authoring-exact-manual-revision/1`，记录父资格、根候选资格、原章节与新章节、原请求摘要、操作者、命令、节点、修改文字摘要及理由 |
| 结论区分 | 人工资格明确设置 `candidate_adopted=false`、`content_correctness_certified=false`；原候选资格与消费回执保持不变 |
| 写入 | 原稿由数据库读取后在服务端重建，使用现有共享保存边界追加新修订；不是修改历史行或由客户端传入完整替换章节 |
| 来源 | 根固定编写输入、引用和规则关联不变；当前规则、事实、来源、祖先状态和生命周期仍由原生授权检查控制 |
| 原件 | S3 读取在草稿和来源事务关闭后执行；最终事务重新捕获完全一致的原件/来源/快照关系，不接受核验期间发生的变化 |
| 数据库守卫 | 原 B3 校验函数保留为私有候选校验核心；可选扩展按实际人工记录分派，不接受 caller mode；递延触发器校验完整资格、正文、前后快照、审计和命令回执 |
| 幂等恢复 | 先查询原命令，重放原请求、原 If-Match 和原操作键；原回执不依赖当前来源仍有效，来源失效只阻断新使用 |
| 浏览器恢复 | 保存发送前持久化完整原请求与原稿资格；网络异常、未核验 2xx、401/403、未知冲突均保留记录；挂载、刷新能力或恢复连接不会自动发送命令 |
| 冲突恢复 | 只有明确的 412 基准冲突转为冲突状态；用户须读取并核对更高草稿修订，再保留原文字重新确认；不能直接替换旧请求的条件和正文 |
| 账户与路由 | 恢复记录按成员、项目、草稿隔离；账户切换、卸载或记录被替换后，晚到回执不能清理其他记录或恢复旧账户操作 |
| 权限 | API 只获得新人工表 SELECT/INSERT 和资格投影视图 SELECT；Worker 无法直接读取新表/视图，继续使用窄快照/构建 RPC |

## 安装与兼容性

新增可选 SQL 为 `packages/contracts/sql/authoring-exact-text-edits.sql`，安装次序必须位于固定来源 B1/B2/B3/B4 之后；其中直接依赖 `authoring-exact-revisions.sql` 和 `authoring-exact-builds.sql`。旧 SQL 文件没有改写，原 B3 候选表也没有改为允许伪造人工动作。新 union view 使快照/构建读取实际原候选或人工资格。

该脚本由初始化 owner 在经过验证的目标环境单次安装，API 和 Worker 仍使用独立非 owner LOGIN。没有安装扩展、缺少原构建能力或缺少必要授权时，能力接口明确返回不可用，新增保存返回 `AUTHORING_EXACT_TEXT_EDIT_NOT_CONFIGURED`，历史正文保留。本轮只在隔离的测试数据库安装扩展，没有对用户生产数据库执行迁移。

前端类型由实际 OpenAPI 导出，并在 `generate-contracts.py` 的消费类型清单中注册新增协议。新增恢复键已加入现有账户清理注册表。既有普通保存入口的固定来源限制保持不变。

## 仍明确受限的范围

- 每次修改一个已有纯文字段落或标题；有粗体/斜体标记或硬换行节点的选区、表格、图片、章节结构及引用集合的编辑不属于此资格。
- 单次文字最多 20,000 个字符，理由最多 1,000 个字符；数据库按真实父链验证，最多连续 128 层人工派生资格。
- 新引用、新规则、新章节结构或富内容需要独立来源资格方案与验收，不能用此接口或普通保存绕过。
- 尚未确认发送的表单文字留在当前界面，导航及刷新有未完成修改保护；已发送请求具有浏览器会话内的完整恢复记录。浏览器主动清除站点数据不属于持久服务端草稿存储。
- 此阶段可以记为“固定来源单段人工文字修订闭环完成”；不得据此把全部富内容采纳、真实业务验收或整项目进度改报为 100%。
