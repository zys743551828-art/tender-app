# 标事台｜生成标书功能设计

状态：已实现**单标段技术标（施工组织设计）可编辑初稿**的单章链路，以及内部 Word 核查和确切包修订交接。独立评审授权、正式候选件下载闸门和真实项目试点尚未完成。本文第 1–6 节为目标方案，已实现范围与验证边界见末节。首期输出是单份技术标草稿，不是全套投标文件；不签章、不上传交易平台、不自动提交。

## 1. 范围与用户路径

| 阶段 | 提供 | 不做 |
| --- | --- | --- |
| P0 技术标（本设计的首期） | 单标段；审批后的目录、逐章生成和编辑、证据覆盖表、内部预览、对接独立评审、按项目规则核查后产出可供人工提交的技术标 DOCX | 商务标、报价标、整包；不自动生成工程量、施工承诺、图纸、甘特图和专项施工方案，不承诺正式评分 |
| P1 商务标 | 招标原表单套填、企业与人员资质目录、证书和业绩附件；由专人确认主体、证号、范围、有效期、原件及可披露性 | 不生成或修改证书、签名、印章、授权、业绩证明；缺项保留未填，阻止该部分成为候选件 |
| P2 报价与拆包 | 使用人工批准的清单、单价、计价口径、税率、币种和精度输出报价表；确定性核算单项与合计，独立确认最终价格；按招标要求组装卷册 | 不把现有模拟报价当真实价格、不补猜量价、不自动投递。多标段后置，每标段单独冻结、核对和导出 |

项目内沿用“编写”页（`/bids/:bidId/authoring`），在概览和编写页加“生成技术标”入口。回到原项目和原草稿，不再要求重复上传。

1. **锁定标段和依据**：选择招标依据包、工作投标包、标段及轮次；显示已解析范围、未读页、规则有效性、人工确认的事实。跨标段不默认选“最新”或继承事实。若老项目无包，先创建或选择现有包，不创建第二种项目或包对象。
2. **确认大纲**：左侧章节树，右侧原文证据与覆盖表；按指定目录、评审项和强制条款建议章节。确认后才建立章节骨架、保存草稿修订。招标文件禁止的目录、封面或栏位不得强加；未命中显示“待映射”，不是“已响应”。
3. **按章起草**：选章节、显示成本上限并确认；支持部分完成、前后比较、仅重试失败章节、拒绝候选或继续手写。结果是待采用候选，不直接写入正文。采用时核对目标修订；冲突保留两边，由人合并。
4. **自检与送审**：先核对覆盖、事实一致性和版式，可生成“内部预览”。用户显式送审某一版本，独立评审人核对规则、证据与问题；整改或带理由关闭非阻断提醒。修改后新建修订，旧意见仍可读，但不批准新版。
5. **导出候选件**：列明阻断项、文档版本和候选范围；过闸才开放“导出技术标候选件”。若要求上交 PDF 或多卷，首期 DOCX 只表明该组成件状态，不代表整包可投。

界面状态：准备（资料待补 / 可确认）→ 大纲待确认 → 编写（排队 / 生成中 / 部分完成 / 待采用 / 失败可重试 / 费用待对账）→ 待审 / 待整改 → 候选件可导出 / 已过期。上传、解析、生成、评审、文件通过分别展示；状态由既有记录与冻结版本派生，不新增任意跳转的全局状态机。刷新/返回恢复阶段和精确版本。

## 3. 依据、内容与版本

**按作用域认定效力，不靠上传日期。** 先核对招标正文及附件版本；正式补遗/答疑仅在匹配标段、轮次、条款且有真实逐字依据时替代明确范围，其余保留。两个正式来源冲突或范围无法确定时并列原文，请人选据，记录依据、经手人、原因和时间；内部模板不产生招标要求。已确认的项目与企业事实由相应责任人依据真实凭证维护，仅用于事实；历史标书、知识库、通用模板只是措辞/结构参考。缺页、低可信解析、来源冲突或未确认必选条款不得放行候选件；首期 exact 任务若无法满足完整输入也不得发起。

覆盖表保存 `规则/条款身份 → 章节/稳定节点 → 证据`。证据包括 `document_version_id / parse_id / evidence_id / 原始页码、表格或块位置 / 摘录摘要`，可以跳回带版本的原页，不跳“最新”。关键事实保存 `fact_id / digest / 适用标段 / 用途`。来源文本、模板和检索结果均按不可信数据处理，不把其中指令当授权。模型只返回受控文本候选和允许的证据 ID；服务端验证所属范围和版本，引用存在不等于语义正确，仍由人复核。内部证据 ID、原件链接、提示和评审意见不插入候选件；只有招标要求的正文编号/公开引用按人工确认的规范渲染。

| 内容类别 | 处理 |
| --- | --- |
| 已给定约束（工期、质量等级、工程范围、图纸/清单编号） | 依据已确认的原文精确取值；不确定标待补，不按相似项目推断。 |
| 企业承诺（人员、机械、工法适用性、进度和安全措施） | 允许建议写法或待确认项；不说成已有资格、实际资源和已批准施工承诺。责任人核实工法、资源和规范适用性。 |
| 商务资质、证号、业绩、造价 | P0 不取用、不生成；后续只接受有出处的结构化字段，缺失留空，不能用模型补造或改写。 |

计划绑定 `bid_id + 选定工作包和依据包修订/摘要 + 标段/轮次 + 规则清单摘要/来源效力决定 + 文件及解析版本 + 已确认事实和用途 + 目录/样式版本 + 草稿/章修订`，不重复存附件正文。逐章候选记录输入/目标节点摘要、生成策略、模型和价格版本、费用预留及输出摘要。评审绑定草稿快照与构建摘要；候选件记录实际 DOCX SHA-256、检查清单摘要、批准人和时间（可选 PDF 与源 DOCX 对应证明）。新补遗、事实/规则/模板变化、正文修改，均保留旧记录，标受影响章节及旧审批/导出资格为过期。未受影响章节可经人工复用，候选仍按新基准完整复核。

## 4. 导出与独立评审

**内部预览**可在资料不齐时产生，仅供项目成员核查；页面、文件名标“内部预览”，正文可保留待填项。现有产物采用不得把预览当候选。独立评审使用与待发件**字节一致的干净暂存文件**（不是内部预览的副本），仅授权成员能查，待检、拒绝或过期时无对外候选下载。Word 离线改动、重新上传或再渲染导致字节变化时，不继承原审批。

**技术标候选件**用现有可信结构化/富文本 DOCX 组装链，从受控节点、样式、允许素材重建，不接受模型拼装 HTML/OOXML，不拷贝外来 Word 包的隐藏内容或属性。需核对 PDF 页数/分页时，使用既有受控 Gotenberg/执行器和字体；DOCX 成功不代表 PDF 渲染成功。不靠一个暗标开关放行，按本项目有效要求对最终字节核查：

- **结构和渲染**：按项目核目录、节与标题、行距、字体字号及继承/主题、页幅、边距、颜色、页眉脚、页码、页数和附件位置。未要求的不自加规则。缺可用渲染证据时，需要渲染才能核的项标“无法核”，不显示合格。
- **匿名和封装**：检查正文、文件名、DOCX 属性、页眉脚、表图、隐藏文字、批注、修订、水印、域、替代文字与图片元数据；必要时 OCR 后复核或请人查看。按项目规定识别主体名称、别名、徽标、颜色、编号等是否要求、允许或禁止。宏、外部关系和嵌入可执行内容走全局安全基线；内部跟踪、作者属性、评审批注与修订清除。保留招标明确要求的正文标识，不一刀切删图或名称。
- **人工闸门**：未覆盖强制要求、冲突、关键事实待确认、占位符、异常标识或格式、必须但未核的语义/视觉项、无独立评审、版本/哈希变化，任一项阻断候选下载。无法自动判断的规则由有权限的评审人核对原条款与实际文件；不能一键忽略。评审人不同于生成/采用人，无独立人审时只能预览。检查日志、原文证据和评审意见留工作台，不打包。

送审时由人显式采用干净构建为指定投标包**新修订的技术组成件**，不替换其它成员、不等于完整包，按已有流程冻结覆盖、评审及执行输入。机器评审只在已确认适用和已授权时启动；如不具备整包评审资格，可由独立人员审核技术组成件，不得假报“整包评审通过”。不自动重新评审、登记提交或上传平台，不承诺官方分数。

## 5. 接口、数据和故障处理

- **现有接口**（前缀 `/api/v1`）：`/bids/{bid_id}/drafts/{draft_id}/structure` 及结构预览/应用；`/bids/{bid_id}/authoring/package-inputs` 提交精确输入，单独经既有任务受理 exact 生成；`/bids/{bid_id}/drafts/{draft_id}/generation-batches` 是通用批次；`POST /bids/{bid_id}/builds`、`GET /builds/{build_id}` 构建与查看；`POST /bids/{bid_id}/builds/{build_id}/package-adoptions` 显式采用；评审挂到所选包修订的 `requirement-inventories` 下。
- **建议增量**（未注册）：`POST /bids/{bid_id}/drafts/{draft_id}/generation-plans` 创建无模型的预览/确认计划（沿用 preview/resolve 模式），`GET /.../generation-plans/{plan_id}` 查只读状态；`GET /builds/{build_id}/candidate-check` 返回实际字节检查和待办，`POST /builds/{build_id}/candidate-approvals` 记录签收。现有授权下载与采用服务按 `internal_preview / technical_candidate` 分权，避免直接访问旧下载/采用路由绕过。确认大纲不顺手发送模型、发布文件或审批。
- **最小存储**：沿用 PG17 草稿、章修订、作业、预算账、包修订、审计及私有对象；增加不可变 `generation_plan`（输入引用/摘要和条款到稳定节点映射）、`technical_candidate_check`（build ID、检查方法/结果摘要、最终 SHA、审批证据）。审批可复用现有不可变命令记录，不建新流程库。私有对象只用引用和哈希，正文和模型载荷不进常规日志，客户端不见对象键或签名 URL。
- **重放、重试及并发**：沿用 PG Outbox → Kafka → Worker、租约与 fence。写操作带 `Idempotency-Key`/`If-Match`；同键同命令返回原回执，不同请求冲突。版本/权限变化阻止旧任务发布；迟到回包不覆盖手稿。回放已归档的字节可验同一哈希；再调模型属于新运行，不保证相同输出，也不自动换新模型跑旧任务。仅临时传输错误走有界重试；已发送但收费未知需对账，不盲重投。取消停止未发送任务，在途回执可查但不自动采用。
- **成本和安全**：复用模型适配与价格登记、按章/计划限额、费用预留，重试也计入已同意的总额度。通用实现当前最多 20 章、同章 5 次尝试、16 MiB 冻结输入；exact 另有上限，试点取更严格者。费用或能力缺失时先解释，可手工继续。模型只接收经授权且与本章/本标段有关的数据（exact 要求完整上下文时，不能通过省略资料规避检查）；禁止模型用工具、跨项目检索和执行资料内指令。复用会话权限、审计与同源传输；日志只记身份、耗时、费用、分类，不记正文/密钥/原件链接。

## 6. 实施顺序和准出门槛

1. **单章纵切**：合成单标段 → 解析及有效规则（含冲突）→ 大纲人工确认 → 固定节点候选 → 编辑、覆盖复核 → 可信 DOCX。用显式测试模型核对 exact 能力/权限/费用，不以通用模式兜底。
2. **闭环**：区分候选和预览，核查实际字节及暗标/格式，独立批准；串接包修订采用与现有评审。处理失败、并发、迟到与版本变更后才开放候选下载，再扩展多章体验并安排经授权的真实试点。
3. **再扩商务和报价**：以业务确认的脱敏模板定义字段、适用标段、附件以及资质/造价责任人。不做签章或外部投递。

| 合成夹具 | 必须验证 |
| --- | --- |
| A. 明标单标段，12 条人工标注必应要求，工期与验收等级有原文 | 放行前 12/12 有正文节点与可回跳证据，0 条无依据关键事实，0 条虚构数据；Word 可编辑且可送独立审阅。 |
| B. 正文“180天”被正式补遗改为“150天”，其余不变；另含无法裁决的补遗对 | 仅影响的章节标新旧差异，旧候选和审批失效，其余规则不丢失；冲突不自动选择，候选不可下载。 |
| C. 缺页、低可信解析、缺事实、固定输入过大、模型未配置 | 可以说明原因并继续手写；关键数据不补猜、不变成 0；无降级模型调用或候选件。 |
| D. 暗标版式错误，主体别名分别出现在页眉、属性、修订、替代文字和图片 | 每处独立命中阻断或待人工核验；修复后通过；明标夹具的必需标识不被误删。 |
| E. 同键重放/冲突、两人并发、超时收费未知/迟到消息、实际文件被替换 | 同键仅一条作业/一次账务记录；未知收费不重扣，0 次覆盖人工稿；字节不一致或审批旧版本均不得下载。 |
| F. 跨标段/项目证据、越权下载、资料内含外发指令、转换器不可用 | 0 次越权读写、外发或下载；要求的渲染检查没做时不得显示通过。 |

**准出**：A–F 全过，合成集合内 100% 的约定阻断项被拦截，0 个未审批、过期或他项目文件变为候选；至少各用一份合规的明标/暗标 DOCX 由独立人员打开核对编辑、排版、内容并签收。复用 `test_authoring_package_inputs_pg.py`、`test_authoring_package_jobs_pg.py`、`test_authoring_generation_batches_pg.py`、`test_authoring_exact_builds_pg.py`、`test_authoring_package_adoptions_pg.py` 和源效力、审查、构建测试；增加浏览器纵切与真实 DOCX 字节检查。合成测试不用真实客户资料或外部模型，不以预测或中标率做验收。下列增量的机制验证不等于全部准出。

## 当前实现记录

首个增量在现有“编写 → 章节目录与计划”中提供“生成技术标大纲”。可明确选择同标段和同轮次的两份包修订与当前要求清单，由已确认、适用并有依据的技术要求建议空章节，可查原页，随后通过既有目录预览与人工应用新增；不覆盖现有稿件。技术大纲预览与确认在服务端锁定并复核当前投标包、依据包、清单、规则、决定及来源效力。服务器从已支持的建议派生追加空章，普通目录编辑不能将任意标题标记为已绑定的大纲。已完成动作可按原命令恢复；基于旧客户端且无固定依据的未应用预览必须重新创建。这仍不是固定编写输入。章节计划中的正式证据绑定、固定上下文生成、候选放行与独立审批仍遵循各自步骤，不因此自动取得资格。

第二个增量在成功的 Word 构建下提供“技术标 Word 检查（送审前）”。接口只对指定的不可变 DOCX 执行字节与 SHA-256 核对，回报作者、隐藏内容、修订、批注、外部关系、项目输入的禁止标识等问题；不保存输入、文件修改、审批或采用。项目名称与别名由操作者依招标要求输入；该清单和拟用文件名不会成为权威规则也不会重命名文件。无机器问题不代表满足暗标；渲染、版式、图片和原条款须独立人工核对。现有文档下载和包采用仍非最终交付闸门；候选件审批与下载权限分流尚未放行。

第三个增量在已有章节中增加“准备生成本章技术标候选”。先获取已保存的草稿/章节修订，再通过既有完整固定输入和模板链进行编写；列表不会把其它章节、快照或修订当当前输入。模板保存仅登记，不启动模型；从精确链接打开任务确认并手动启动。候选、采用与构建继续走现有分别确认的路径。如果运行能力未配置、证据变更、已保存的输入不匹配，仍不自动退回通用生成。没有新增收费路径或对外导出权限。

第四个增量在固定整包章节任务的手动运行入口显示当前价格版本对应的系统费用预留上限（不是供应商的账单上限）。新运行在应用页面必须先读取与有据模板修订一致的报价，且在受理时复核价格和金额；变化或缺失时不发起新模型调用。已有运行、未知费用的对账与原回执恢复不改写价格或再次扣费。新公共真实收费请求缺报价也会被拦截；保留旧原键回执与显式测试适配器的旧夹具兼容。

显式采用成功后支持从已核验的回执打开确切包修订做内部核查，链接不会改指最新版本，也不发起评审操作。此时仍不具备正式独立审核授权。独立审核与正式候选下载后续必须新建项目级 reviewer 授权与职责分离，绑定确切包、规则清单、草稿、实际文件 SHA 与审阅记录后，在下载时实时复核；现有内部文件下载不可冒充已经批准。

Word 核查会对照本构建快照中已经人工确认、携带原文证据的页边距字段，读取实际 DOCX 主文档各可识别节的 XML 原始数值（twip）。模板默认值不算招标要求。没有此类冻结依据时显示人工待核；依据残缺、分节无法识别、或数值不符时显示需处理。部分字段匹配不是整页通过，镜像边距、实际排版、分页及与当前招标要求是否一致仍应人工核对。该结果与构建身份、文件 SHA 和检查依据摘要对应，不保存为批准。

合成纵向测试已经用固定单章输入、显式测试模型、人工采用和真实 Word 组装验证字节摘要一致；未调用真实模型、未使用投标原件，未做正式独立签收、实际交易平台上传或 A–F 完整验收。发布前仍须解决成员与项目权限、独立评审身份及职责分离、候选件下载隔离和实际 Word 渲染复核。

确切包修订页可手动读取生成技术稿的直接采用回执。只读接口核对冻结包、文件/解析、同一采用命令的资格记录与原回执；不读取对象字节、不把复制到新包修订的成员认作新采用。它只报告采用时记录的 SHA，不显示当前字节、来源、版面或资格已复核。已有报告必须对应同一包修订、文档版本、文件摘要与解析，才汇总明确列出此文件的条目及其最近读到的人工意见；不是技术分册覆盖率，也不新增读写工作流或权限。未读、错配和过期均不能继承结果。现有构建下载仍用于内部预览与编辑。此读取按单修订、人工触发且限量；推广到大规模审计表前需验证查询计划，并按项目/事件/修订评估索引或独立投影。

编写页可在同一技术要求清单中展开“技术要求与已存章节对照”：按已存正文关联和同版本计划分别列出章节，旧计划和未绑定原页单独提示；原页跳转核对明选依据包的文件与解析。它只显示规则与引用身份是否能对上，不比对条款正文是否实现、不确认来源仍有效，也不用于计算覆盖率或批准。依赖缺失、未确认条款和未分类范围仍需人工核对。

内部 Word 核查对实际 OOXML 的正文（包括表格单元）、页眉页脚和脚注/尾注读取可提取的段落文本，提示明确的模板占位符（如双花括号或带括号的“待填写”）。同段落跨格式分段仍能识别，不跨段误拼；报告只给代码，不回显原文。普通“待补充”措辞、缺数据、版面及事实语义仍需人工检查；未命中不等于文档完整或可投。

从章节返回或刷新时，可再次打开“生成技术标大纲”恢复本账号、本项目、本草稿在当前浏览器会话上次明确核对的包和清单。只保存 ID 和摘要；读回时重新校验项目、版本、摘要、各包当前头与当前要求清单。源变化不改用新版本，须人工重新选择；不恢复审批或生成授权，不自动发起任务。

在“准备生成本章技术标候选”的固定输入采集里，可核对并明确带入同草稿会话的大纲资料选择。仅可填入尚未选择包与事实的表单；读取要再次匹配当前两包和要求清单，不采用变化后的替代项。带入后仍必须选择已存正文的稳定节点、有效事实和用途，走原固定输入保存、费用确认与手动运行。没有为历史选择增加生成权，也没有新增网络写入或对外操作。

本章固定输入直接核对已知项目、草稿、快照和章节修订，不要求在历史快照目录中逐页找当前章节。读回摘要、本章正文身份和当次草稿头观察均匹配后，需要点击“使用本章已保存版本”；此按钮只选范围，不自动选文字节点，不用最新版本代替读失败或旧版本。通用采集入口仍可获得原历史目录。

本章可手动查询已保存固定编写模板，无需依赖原页面或浏览器缓存。目录按观察到的确切草稿和章节范围，只读验证当前模板版本、固定输入摘要和正文绑定；同章不同快照标记为非本次正文，数据不可用和没有匹配记录分开提示。每次最多显示 12 条，不读固定输入上下文正文，不概括是否运行、是否采纳、来源是否当前有效或是否有提交资格。任务页链接明确为重新读取模板当前版本，不运行任务。

本章模板可按确切模板版本和固定输入手动查看原生运行记录。仅显示最近 3 条；重用既有运行、计费对账及候选发布证明，并区分待发布、已发布、失败、取消、过期、待对账和无法核对。版本改变后仍不把另一版本的运行接到当前卡片，也不把已发布当正文已采用或文件已批准。该目录不发起模型或写入；不能核验的记录没有跳转入口。

原生纵向夹具补验带真实持久化身份的结构化路径：按已确认清单应用进度与质量空章，先在原版式流程人工核对并确认应读未判明范围，再固定进度章的空白节点，以一轮离线模型运行取得候选、显式采用并按冻结的目录和版式构建可编辑 Word。质量章原样保留；核查匹配同一实际文件 SHA，不入包或登记提交。这是内部机制验收，不表示已核完版式语义、更不表示通过正式审阅。已有固定修订不能通过普通目录操作补做版式；结构稿应在第一次运行与采纳前完成该核对。
