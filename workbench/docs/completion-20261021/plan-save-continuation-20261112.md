# 章节计划回执与同章继续编辑

日期：2026-11-12。范围是 FR-037 章节计划保存与正文自动保存的衔接，不改变模型、数据库、导出协议或业务资格。

## 反例与修正

实际 Panel + SectionEditor 的合成 HTTP 测试，在已提交的 `ea26cc2` 源码上复现：草稿修订 1 保存章节计划得到修订 2；不切章继续修改并保存正文，编辑器仍发送修订 1／旧 If-Match，而不是修订 2。严格模拟服务器拒绝旧版本后，测试失败。原始失败日志仅留本机，不入 Git。

- 计划保存成功时传递真实 `AuthoringPlanSaved`，不伪造结构 `state=applied`，也不把一般刷新／冲突读取当成成功写回执。
- 只有核对保存回执、草稿及快照，且前后仍是同一个已保存、无恢复／章节操作中的编辑器，才重新读取正文。读取失败或服务器出现更新时，保留旧正文与本地副本，明确重读只执行 GET，不重新发送计划保存。
- 在命令 hook 清除原恢复记录之前校验回执外层草稿、计划内层标书／草稿／章节身份、正安全整数修订与非空快照 ID。畸形成功响应保留原请求，可按原 body、key、ETag 恢复，不误报新保存头。重放旧回执不要求等于当前计划修订加一。
- 412、明确拒绝、未知回执、恢复原请求与读取当前计划的语义保持；未知回执不能新建请求或静默丢失当前正文。
