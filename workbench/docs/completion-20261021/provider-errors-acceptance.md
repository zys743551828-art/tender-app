# 独立用途错误模块与业务配置隔离验收

图文端口和JSON协议只导入纯错误模块，不再因共享异常类型进入业务runtime或旧文字客户端。`runtime.DomainError`和`deepseek.ProviderError`保留原导出路径并指向相同类对象，旧构造、属性和错误计费语义保持一致。既有API处理器实际处理三种错误，返回422／503和原错误结构，响应原字节不外泄。

导入验证在全新`python -I -X utf8`子进程和系统环境白名单内进行，将`.env`存在性和读取模拟为合成配置；不访问真实业务配置。修复前两个用例均失败并观察到一次合成配置读取，修复后均无runtime／旧文字端口导入、无配置读取或标记环境变量。兼容验证在独立ASGI应用复用实际异常处理器，不向主应用添加测试路由。

最终Linux Compose固定套件296项通过（7.62秒），Windows端口及兼容67项通过（3.49秒），本机完整API快照／生成TypeScript 11项通过（4.35秒）；套件范围重叠，不累加为项目完成数。九文件Ruff／format、八实现mypy／Bandit通过。原错误类、runtime其余执行体、文字端口、图文端口和JSON协议执行体AST保持；判断／依赖序列化方法明确绑定两个纯错误文件产生新摘要，输入／特征方法及受限原页七文件来源摘要不变，旧回执不回填。

本机API已重启避免新旧异常类混用；5188的1184运行输入与68个JS／CSS逐字节匹配，登录／会话／退出、匿名拒绝、缺项目和非法参数错误通过，业务项目与付费调用0。API／Web／PG健康，检查库／临时LOGIN0，checks／检查PG／原页派生服务停止。正常Word及其他环境保留。运行文件为开发只读挂载观察，不冒充不可变发布。

初次兼容子进程未显式指定UTF-8，Windows导入中文契约时GBK解码失败；已限定子进程UTF-8。初次Linux套件包含需要前端生成器的完整快照测试，而检查组不挂载前端脚本；Linux保留实际快照／导出一致性，完整生成与格式后的字节比较使用已有Node的本机环境通过，未扩展挂载。原失败与最终结果都见[证据回执](evidence/provider-errors/receipt.json)，OSS依赖弃用及PDFium提示保留。

本批没有新增HTTP接口、SQL、前端或模型外部请求。浏览器缺服务模块的视觉验收缺口仍存在；独立当前输入权威／必要范围核验、token／费用、持久化／租约／账本及正式Worker接线继续。
