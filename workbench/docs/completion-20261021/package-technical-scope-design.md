# F06：当前整包技术范围冻结设计与边界

状态：当前整包技术范围已经接入主 API 与 BASE SQL，并通过独立 PostgreSQL 17.11 非 owner 验证。本文对应范围冻结片 `current_prebid`；其后新增的只读评分／样本上下文及可选满分权威接线，见 [本轮验收记录](technical-scope-acceptance.md)。正式评分、历史样本和训练入口仍未开放。

## 本片保存什么

技术范围绑定同一项目身份下的一版完整本方包、一版权威包、一份准确要求清单，以及这些对象的原摘要。调用者逐项声明全部已识别评分条款的 `include`、`exclude` 或 `unclassified` 状态，并为纳入项指定本包技术章节。服务不能以当前材料、最新解析或某个包成员替代上述对象。

预览保留完整包成员目录、所有声明章节、全部已识别评分条款、准确物理页、实际解析证据块、原表格结构文本和权威原文引用。未选择的章节仍在记录里；排除条款仍保留原规则、依据与人工理由。纳入或排除条款都要求其全部原证据确切来自所选权威版本及已声明物理页范围；证据不足时只能保留待分类。

服务按章节完整页范围读取；容量限制超出时整件拒绝，不分页遗漏分母，也不默默截断正文。当前容量为每包 500 个成员、2,000 个本方章节、1,000 个已识别评分项、100,000 个物理页、100,000 个证据块、20,000 行来源祖先关系；请求最多 1 MiB，完整冻结快照最多 32 MiB，原件流式核验总量最多 1 GiB。

## 明确保留的未知项

范围选齐、逐页有文本、人工确认或规则清单的旧 `complete` 标记，都不能证明全图表已被正确理解，也不能证明实际评分条款及所有适用范围穷尽。预览和存储协议因此固定保留四项缺口：清单完整性未证明、图表完整阅读未证明、必要技术范围完整性未证明、模型执行未开放。

实际未选择章节、缺准确冻结解析、空证据页段、解析原缺口、缺权威引用、遗漏既有声明章节、人工排除和待分类状态会分别追加可核对的缺口。数据库从原始记录及所声明选择重算这些缺口及数量，不接受写入者自报“完整”。

以下五个字段在预览与冻结记录中恒为 `false`：

- `inventory_complete`
- `scoring_ready`
- `formal_scoring_eligible`
- `model_execution_enabled`
- `training_eligible`

本片没有创建评分任务、三次判断、模型调用、训练样本或费用预留的接口，也没有给予 Worker、评分角色或研究角色新的执行权限。

## 时间与事前边界

本片只接受当前事前用途。项目关闭、终止、归档、阶段为 `submitted`，或统一 `submission_heads` 已存在实际提交记录时，不能新增当前事前范围。即使项目随后恢复到其他阶段，已存在的实交事实也不会消失；历史实交输入要走后续独立的严格协议。

`frozen_at` 是系统实际登记时间。`historical_as_of`、`submitted_at`、`label_known_at`、`training_frozen_at`、`submission_split_at` 和 `label_available_as_of` 在本片均为 `null`，并明确标记 `historical_qualification=not_established`。这些空槽不能从文件名、当前时间或人工点击推断补齐。

历史详情和原成功命令回执继续可读；事后的来源撤回或项目状态变化不会把旧回执改写为另一事实。

## API 与命令身份

共同路径为 `/api/v1/bids/{bid_id}/packages/{package_id}/revisions/{revision_id}`。

| 方法与路径后缀 | 作用 |
| --- | --- |
| `GET /technical-scope-context?inventory_id=...` | 返回完整准确选择、方法、可冻结状态和强 ETag |
| `POST /technical-scope-previews` | 只读重算范围、原页证据和全部缺口 |
| `POST /technical-scopes` | 按预览摘要与原强 ETag 冻结；返回 201 原始回执 |
| `GET /technical-scopes` | 按实际登记时间分页读取摘要；每页最多 50 条 |
| `GET /technical-scopes/{scope_id}` | 读取该准确包的不可变完整记录 |

冻结请求为 `{request, preview_digest}`。原命令摘要使用既有 canonical JSON SHA，绑定 `{body: {scope: [bid, package, revision], request, preview_digest}, if_match}`。回执包含原 `command_id`、`actor_id`、幂等键、请求摘要、原请求和强 ETag；同键不同请求或条件冲突，同键同请求则优先返回原成功回执。

浏览器读取使用会话认证；预览与冻结沿用 CSRF 和 Origin 校验。只读请求使用 `REPEATABLE READ READ ONLY`。未安装新表、缺最小列权限或缺已审 UUID 扩展时如实报告不可用，不把未装配的能力显示成可提交。

## 原件核验与最终事务

第一次只读观察冻结准确包、清单、项目身份、包头、清单头、统一提交头、生成稿资格和全来源祖先状态。原件及每个冻结解析的规范来源根由既有 `original_source_id`、`parse_source_id` 规则确定；每根必须有自身闭包边，所有祖先必须在同项目、适用于事前内容、已发布并满足取得时间与有效窗口。

数据库连接关闭后，服务按实际对象键流式读取全部直接原件和有原件的祖先，核对 SHA 与字节数。私有对象键不进入公开协议。最终短事务按项目、来源图的既有锁顺序重新观察全部输入与方法；强 ETag、预览或任何来源状态变化均拒绝新记录。原件读取期间不持有数据库事务或图锁。

范围、审计及命令成功回执在同一事务提交。追加记录不能更新或删除；延迟约束要求回执和审计精确绑定该记录。对象核验成功仅登记为 `verified_at_recording`，不会把预览里的 `original_bytes_verified=false` 或完整性未知改写成评分资格。

## SQL 与方法的信任边界

新 SQL 只增加范围存档表及相关校验函数。数据库根据原生包成员和固定 UUIDv5 名称空间重算所需原件与解析根，验证全祖先集合，重建章节页块、权威引文和覆盖计数，并拒绝缺失或 `null` 数组、范围伪造、缺依据排除、伪造缺口和执行资格字段。

`context_digest` 和源码方法摘要由 API 在原件 IO 前后独立重算。数据库不能读取应用源文件，因此只验证方法的闭合协议、固定源码文件集合、常量容量限制与内部摘要；这不是数据库对当前运行源码的独立认证。任何未来评分消费者必须重新验证受信方法与当前资格，不能仅凭该存档或自签方法摘要执行。

所需新增原生依赖为 PostgreSQL 官方 `uuid-ossp` 1.1，固定安装到 `public`，仅由新库初始化 owner 安装。业务角色没有数据库 `CREATE` 或对象所有权；API 只取得所需 `uuid_generate_v5` 执行权。缺扩展文件会中止安装，不降级为信任请求里的来源 ID。官方构建方式及 UUIDv5 语义见 [PostgreSQL 17 uuid-ossp 文档](https://www.postgresql.org/docs/17/uuid-ossp.html)。

## 当前验证记录

- 范围纯回归 42 项通过，覆盖全部章节与条款选中仍不授资格、同包未选附件保留、遗漏条款与跨修订拒绝、精确解析绑定、无依据纳入／排除拒绝、实际提交后不得冒充事前、方法自签拒绝、原件与解析根缺失、跨项目、标签用途、撤回与时间窗口、全部祖先原件回执绑定。
- 范围原生 PostgreSQL／ASGI 29 项通过，包含 SQL 不变量、独立非 owner API／Worker、双重观察、并发原回执、延迟审计／回执约束以及锁外原件流式核验。
- 新只读资格纯测试 30 项和原生 BASE-only 测试 4 项通过；可选满分登记／完整身份适配原生测试 5 项通过。与既有量尺纯测试共同运行共 117 项通过。10 个定向源文件通过 mypy，15 个源文件／测试通过 Ruff 与格式检查，10 个源文件通过 Bandit。
- 验证使用独立临时 PostgreSQL 17.11 prefix、pgvector 与 `uuid-ossp` 1.1，每套原生测试创建新隔离集群；旧实例、旧数据库及旧工作树未被修改。原件、表格及官方结果均为显式合成，未调用模型，也不证明真实标书质量或正式预测效果。
- 详细命令、SHA、原生回执与后续边界见 [本轮验收记录](technical-scope-acceptance.md) 和 [机器检查记录](technical-scope-checks.json)。

## 后续三判断与历史适配边界

后续继续复用唯一项目身份、统一实交记录及官方结果，而非以本包第一个成员冒充正文。历史分支需要冻结真正实交包、原技术范围、独立原权威分值、所有原件的事前可得性与完整来源链，并分别核对实交时间、事前截止、标签已知时间和训练冻结时间。

正式评分适配应在既有输入、任务、调用预留、费用核算和结果 RPC 中增加精确整包分支，保持三次判断各自独立调用身份、无前次答案污染、未知费用不重试以及原成本账本。新的整包方法和图文完整覆盖证明必须有独立身份；不得把旧单正文方法摘要直接贴给新包协议。

官方技术标签不能进入任何事前评分上下文或用于反推分母。历史严格样本准入、标签时间切分、训练来源与模型接纳仍是后续独立工作；当前范围记录不能使这些资格由 `false` 变为 `true`。
