# 逐条依赖清单容量与恢复验收

本检查点修复要求清单可读取 10,000 条、依赖声明却最多 500 条的范围不一致。每次核对与保存仍提交同一准备输入的一份完整标注集合，未合并分批评估结果，也没有自动推定遗漏条目无需事实。

## 实际实现

| 事项 | 本次行为 | 保留的边界 |
| --- | --- | --- |
| 声明数量 | 实际 API、纯领域 Request、Save 及前端结构校验均允许最多 10,000 条依赖声明 | 10,001 条拒绝；事实选择及单条事实、证据 ID 列表上限仍为 500 |
| 核对与历史分页 | 两处每页最多渲染 20 条要求，可前后翻页或选择页码；显示全局要求序号 | 编辑未应用时不能翻页，避免隐藏未完成的单条编辑 |
| 草稿 | 已应用标注跨页保留；核对时提交全部本轮标注 | 浏览器刷新、离开仍会丢失未保存的标注，界面已明确说明 |
| 大清单校验 | 按要求 ID 建立 Map，事实选择及规则证据使用 Set | 保留重复 ID、未知 ID、摘要、声明字段与资格标志校验 |
| 新请求业务预算 | 新核对和新保存的最终紧凑 UTF-8 JSON 最多 4 MiB | 保存预算包含 `assessment_digest` 和保存理由，不只检查内层标注 |
| 传输预算 | 两个 POST 的实际 HTTP 正文最多 5 MiB，包含 JSON 空白、转义字节，与现有 nginx 5 MiB 一致 | 新请求另受 4 MiB 业务预算限制；正文超限返回 413 |
| 原保存回执 | 保存入口先只读核对原 actor、目标、幂等键与完整请求摘要，并核验原计划回执；匹配后直接重放 | 旧已接受的 4–5 MiB 请求不会被新的 4 MiB 新写预算挡住；未命中旧 ACK 才检查新写预算 |
| 浏览器恢复 | 新保存发送前检查 4 MiB；恢复只重放原键和原体，允许现有 5 MiB 传输范围 | 超过传输上限时保留原恢复记录，可只读查阅服务器历史，不把记录标为损坏 |
| 容量拒绝 | 新保存收到 413 时清除此次明确未受理的 pending 标记，保留候选及理由 | 恢复旧未决请求收到拒绝时，不用新标注替换原请求 |
| 本机存储满 | 发送前写恢复记录失败时不发 POST，保留页面标注和既有恢复记录 | 不声称已经保存；该回归使用显式合成的 `QuotaExceededError`，不是浏览器容量实测 |

结构校验与发送预算分开：历史计划读取和本机原请求的完整性核验没有套用新的 4 MiB 发送限制。依赖协议 schema 参与 `policy_digest`，因此本次改动会使旧的未保存评估不再匹配当前政策；新保存仍返回 `PACKAGE_INPUT_DEPENDENCIES_CHANGED` 要求重新核对。已保存计划按原身份和摘要读取，不按当前政策重算；把历史计划用于新执行仍需要执行入口自己的当前政策核验。

## 验收证据

后端新回归最初得到 **6 失败、2 通过**，复现了 501 条被拒、超额请求进入处理及 HTTP 正文未设限。实现并补充历史 ACK 兼容后，新文件 **9 项通过**；连同依赖评估、归档计划既有回归共 **52 项通过**。

前端容量初始 6 项均失败；实现后，容量文件的 **8 项**连同父子工作区、计划协议共 **53 项通过**。覆盖：

- 501 条完整标注经实际前端协议校验，保存后合成丢 ACK，刷新后仅显式动作重放原体和幂等键，取得原回执；原回执每页只显示 20 条。
- 在 501 条清单的第 1、2、26 页分别编辑，第一次核对合成返回 413 后标注仍在；再次核对与保存包含跨页三条标注，其余 498 条保持未知。恢复保存回执不重建为当前草稿。
- 10,000 条完整声明在领域评估中成为 `declared`；10,001 条拒绝，空缺声明保持未知；这些状态均不证明事实资格、要求语义完整性或评审就绪。
- 中文请求按 UTF-8 字节计数；核对体可小于 4 MiB，而加入保存元数据后的最终 Save 超限时，前端不落 pending、不发送、不丢候选。
- 500 条合法旧请求总量位于 4–5 MiB，服务端按精确旧命令核验并返回原 ACK；浏览器也能重放同一较大原请求。新超额请求仅允许只读查 ACK，不能进入新的写事务。
- 真实 FastAPI 路由的 ASGI HTTP 正文恰好 5 MiB 可处理，多 1 字节返回 413 且不进入业务服务。沙箱内同步工作线程桥会卡住，此测试仅将该调度桥替换为同线程调用；路由、JSON 解析、异步字节限制依赖及错误响应仍真实执行，不作线程或部署验收声明。

## 执行容量是另一项条件

本改动支持较大清单的人工标注、核对与归档，不改变 `package-review/1` 当前最多 400 条要求、4 批模型调用的执行限制。超过执行容量的计划应在执行入口明确拒绝，不能截断后把部分结果标为全量完成。真实语义完整性、模型效果、正式评分和投递资格仍须分别验收。
