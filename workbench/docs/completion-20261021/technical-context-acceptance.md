# 核验上下文与最终输入单向绑定验收

## 契约

独立核验需要固定被核材料，最终输入又需要固定核验回执。两者直接互相算摘要会形成循环，因此[输入契约](../../packages/contracts/package-technical-input.md)提供两个独立阶段：不含回执字段的`package-technical-context-projection/2`先冻结为核验context；独立原生权威后续返回确切context／方法／核验ID／真实回执摘要；最终输入再引用该回执。context不接占位字段，全零回执拒绝。

context与最终输入共用材料、原文、页图、角色和章节闭包检查。绑定前重建context及其摘要，重新核全部资产；不同回执产生不同最终输入，不修改原context或旧报告。context类型不能送入图文序列化器；绑定后的完整输入仍保存所有材料并走实际序列化。

`bind_input`只绑定独立返回的原生记录及其外部预期摘要，不验证签名、发行方、内容真实性、必要范围或当前来源。当前测试记录是显式合成对象，没有原生核验注册表或独立LOGIN安装。正式入口必须用最小权限适配器读真实记录，不能接受用户JSON及自算预期值；所有输入与执行资格仍false。原纯材料构造器同样只授一致性，不能借其绕过正式路径。

新增context流程改变输入源码／契约，因此当前输入方法及依赖它的图文序列化方法产生新摘要；原图文判断方法和特征方法不变。旧记录和旧验收收据保留其原字节与原方法，不能把当前实现的摘要回填过去。历史阅读不需要重新构造为当前方法，旧context用于新绑定须有相应方法的实际执行环境。
