# 固定整包章节编写前端验收（B2）

本批把已保存完整输入接入手动模板、私有任务草案、原生任务结果与候选操作卡。完整输入由 B1 保存；这里从目录明确选择一份，不自动选择第一条或最新条。首份输入的完整采集工作面属于下一批；空目录如实显示缺少输入。

## 用户可完成的流程

1. 在「可复用任务」新建固定整包编写模板，明确选择输入，核对双包修订、要求、事实用途、正文快照和目标节点，填写名称与指令。保存模板不创建运行。
2. 也可用自然语言生成自己的任务草案，再明确编辑、只保存草案，或保存为模板。自动或不明确的要求保留待明确项，只有明确改成手动章节编写才可保存这类模板。
3. 明确手动生成，始终发送 `rerun=false`；B2 执行能力与 B1 捕获能力分别核验。原输入的 `generation_available=false` 不被误当成 B2 不能运行，也不会被改写。
4. 读取真实任务和候选发布状态。模型计算完成尚未发布时不显示“候选已完成”；费用未知、取消、绑定损坏均保留实际状态。完整原稿、拟稿与文字增删可逐项核对。
5. 候选卡允许明确拒绝；本批正文采纳与后续构建尚未接通，对应按钮禁用。没有把提案发布解释为正文已更新。

## 身份、重复任务与恢复

模板请求、已保存输入、任务冻结配置、原生 job／plan／operation 以及发布 action 均使用闭合协议核验。公开上下文删除了私有存储字段，前端明确不声称重新计算其私有完整摘要。输入清单本身及公开可计算的模板／运行配置摘要按规范 JSON 核验。

同一任务的冻结身份在后续刷新中不能改变；刷新损坏或降级时保留最后一次已核验记录供只读查看，不落入旧章节任务分支。完整候选也不能换成其他 job 或输入的结果。

模板和运行在发送前保存原成员、项目、完整请求、条件头与幂等键。丢失 ACK 或响应身份不符后，刷新恢复使用同一请求，当前模板变化不能改写它。恢复原受理回执与 GET 当前运行分别处理；原 ACK 可以来自已结清的原任务，不强制改成当前成员创建的排队态。

相同实质上下文、标准化指令和执行策略复用原任务。新输入编号、模板名称、模板副本或版本不形成新付费意图；跨模板／版本返回的原任务链接必须绑定同项目与合法 UUID。绑定损坏、未知命令结果、未知 409、401/403 或服务错误继续保留未决原请求。仅明确未受理的已知拒绝可以清理恢复记录。

私有草案沿用原有草案命令恢复机制，并在 B2 创建／修改／保存回执中核对原请求、来源、成员、修订、ETag 与配置摘要。真实 revision 1 → 2 → 保存模板 → revision 3 响应，以及每步同键原回执，均作为未经改写的前端 fixture。丢失“只保存草案”回执后仍只保存草案；原模板保存回执可在草案当前修订已前进后恢复。
