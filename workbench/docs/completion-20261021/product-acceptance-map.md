## 口径

- 目标是完整投标工作台，废标／否决风险与施组评分预测是并列 P0。缩小到整包审查试用只能作为一个中间里程碑。
- 主任务表名义状态为：已完成 8、进行中 11、待开始 97、待外部输入 2、待验证 1、范围外后续 1。该分布不是可用产品的完成百分比；旧模块中存在大量可复用代码，新的整包身份、执行与交付仍须重新验收。
- “已有可复用”指已读到实际实现，不代表该能力已经在新工作台端到端接通、跨角色集成通过或完成真实业务验收。目标契约、历史截图、测试适配器和 README 宣告均不单独构成通过证据。
- 本轮不调用付费模型、不写入外部业务环境、不把合成样本用于证明实际准确率。软件验收与 G6 真实业务效果分别记录。

## 实施关键路径

1. **先恢复现有正确性。** 合法受控 Word 的完整来源链、跨面板旧请求失效、退出清理；随后修复证据状态一致性、公平调度、独立输入 guard。回归必须证明允许正确输入且保留拒绝错误输入，不以扩大放行范围消除错误。
2. **完成可复核的整包执行。** 以 exact frozen/prepared 输入为执行边界，正式读取依赖计划，检查原件和来源时效，逐条输出 coverage/issues，并通过 durable operation、取消/恢复和发布 fence 进入可读取结果。拒绝/未知/不可判定均有原因；不能把执行准备成功叫做评审完成。
3. **接好交付主线。** 前端展示当前输入、各册缺口、风险定位、规则确认和下一步；问题处置、复核、两轮对比、报告导出、提交门禁共用同一身份，不再从旧单正文接口隐式取最新值。
4. **平行推进 M1 和可复用模块融合。** 人工编写/精确构建可先完成；AI、知识、报价、任务逐项接入有版本的输入与正式动作。评分 P0 的完整输入和拒绝条件可以实现，但有效准确率仍受真实配对资料限制。
5. **完成软件验收与移交。** 新库角色/迁移、前后端契约、局部回归→集成→合成完整流程→隔离恢复，留下运行命令、实际输出和已知边界。只有真实资料和环境具备时才填 G6 结果。

主计划的 G1→G2→G3/G4→G5 依赖保持；分支内可以并行实现互不冲突的代码，但不得把部分类型的试用路径标成完整 G2/G6。外部缺料时，仍可完成输入校验、拒绝条件、数据导入工具、影子评估流程和验收脚本。

## 通过证据与本轮范围

- 每项变更应有：问题/目标、输入身份和行为、至少一项针对真实失败路径的回归、适当静态检查、提交 SHA、未验证事项。使用 fake DB/SQLite/合成 PDF 时明确标记，不宣称真实 PG/Kafka/转换器通过。
- 三处小修复的独立审查已检查：Word 仍保持祖先时效与完整受控关系校验；busy 仍由 ticket 防旧回包；退出清理同时覆盖命令键与恢复记录、保持成员归属并保留非业务存储。
- 后续已分配的三个旧 bug：证据列表/详情使用同一批量来源状态逻辑；worker 与 review coordinator 有界且公平地轮回；Web 以外的入口显式装配 `TASK_INPUT_GUARD`，保留未装配默认拒绝。
- 当前审计不宣称正式整包 executor、整体 M1/M2、真实预测效果或生产容量已通过；随后实施产生的可执行证据应以实际提交补充，不回写本文件基线为已完成。
