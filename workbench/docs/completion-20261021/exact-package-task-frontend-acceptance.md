# 精确整包手动任务：前端交互验收

本批把明确选择的整包输入接入已有可复用任务界面。模板保存、手动启动、原生核查读取各自保持真实状态；页面贯通不授予正式评分或标准提交资格。

## 可用路径

在整包核查中明确选择已保存的冻结输入、执行准备和依赖计划后，打开“保存为手动任务”。入口读取当前任务能力和项目修订，核对完整来源关系，才显示表单。保存只登记模板，不运行核查。

精确模板使用 `source_selection.mode="exact_package_review"`，保留原包、修订、清单、冻结输入、执行准备、依赖计划及对应摘要。新建和修改均只允许否决核对与手动触发；名称和说明可编辑，固定来源只读。完整身份和摘要可展开核对，主视图提供指向原包与清单的链接。没有把精确来源转换成 `current_project` 或空 `version_ids`，也不请求旧单正文材料作为整包来源。

初始预填值不算未保存修改。用户实际修改后，表单报告真实 dirty；明确放弃文字修改或取得已核验的保存 ACK 后解除。收起表单保留挂载状态，因此不会通过折叠表单绕开未保存输入或未确认请求。

外部模板修订刷新时，编辑器以成员、项目和模板身份保持原会话，不随版本号重新挂载。原文字、原修订基准和导航保护继续保留，界面提示服务器版本已更新。用户必须明确读取并采用新的有效基准，不能自动换头覆盖配置。若固定来源已经改变，则不能把新头用于原来源的编辑。

在“可复用任务”中，精确模板显示手动执行能力及当前方法是否匹配。能力未提供、执行暂不可用、模板暂停、费用待核对、来源方法变更或另一保存/运行尚未确认时，启动被阻止。启动请求固定为 `{ "rerun": false }`；本入口不会创建新的准备输入绕过核账或重复付费限制。

旧四类任务的原有来源、事件和定时编辑路径继续保留。精确整包模式使用独立严格协议，不扩大旧通用命令控制器的接受范围。

## 回执恢复与历史读取

精确保存和启动都先持久化完整请求体、方法、路径、幂等键、ETag 和预期模板快照，再发送请求。只有完整 ACK 校验成功并且原恢复记录仍属于当前会话，才清除 pending 并通知父组件。

网络丢失、401/403、错误项目、错误摘要、错误 ETag 或其他未确认回执保留原请求。刷新后的恢复沿用原 body、原键与原 ETag，即使当前模板已经更新。读取模板或运行历史不会替代原命令回执，也不会产生执行费用。

412 冲突保留输入和冲突状态。界面只有在明确的新读取成功、且确认其身份与基准后才允许新操作；“清除提示”不解除冲突。浏览器存储不足时不发送命令；卸载、账号变化或恢复记录被移除之后到达的 ACK 不会回写旧记录或完成新账号的操作。

原启动 ACK 可以仍为 queued，而稍后的服务器 GET 已为 succeeded。界面分别标明“原命令受理回执”和“服务器当前任务状态”，不把后续结果写回旧回执。

## 原生结果与输入范围

运行卡首先校验完整任务冻结 manifest、包 subject、配置摘要、输入摘要、费用范围和原生运行路径，再显示整包范围。错误的原生路径或伪造包身份不能退回单正文下载或另一个当前运行。

“查看任务绑定的原生整包核查”在点击后读取原冻结输入、执行准备和完整原生 run。它复用现有验证器，继续匹配计划、方法、操作、输入及结果摘要，再使用原生核查工作面展示矩阵、证据和人工状态。`run_ref` 是经过核验的 API 身份依据，不作为普通网页直接打开。

新 GET 正在核验或未通过校验时，已经打开的详情保持挂载，以保留其中的实际操作状态；界面明确标记“上次已核验快照”，写操作暂停。有效新读取到达后才重新启用。固定版本的模板说明也必须匹配任务冻结配置，不显示另一版本的文字。

结果始终保留整体覆盖 partial、正式评分 false、提交资格 false。声明范围内核查结束不等于需求语义完整或业务通过。

## 浏览器证据

[浏览器回执](exact-package-task-browser-receipt.json) 保存三档结果、各场景截图摘要和明确的合成边界。仓库保留 [桌面手动启动](screenshots/package-task-card-1200.png) 与 [手机模板保存](screenshots/package-task-editor-390.png)。完整来源核对区另有展开状态截图，未省略具体身份。

浏览器使用实际非 owner PostgreSQL HTTP 响应和持久化原生运行夹具，原包、模板、任务及核查摘要没有改写。产生这些响应的 Worker 使用合成原件和 MockTransport；浏览器本身通过本地生产 bundle 和明确的 fetch 边界运行。项目基础信息与空的补充目录为专用投影，没有连接生产服务或调用实际模型。

每档均完成：打开真实选择入口、保存且不启动、查看能力、注入一次启动 ACK 丢失、刷新后用相同 body/key/ETag 恢复、同时查看 queued 原回执与 succeeded 当前记录、打开确切原生核查、确认执行不可用时按钮阻断。全程没有旧 `/materials` 读取，页面无脚本错误，宽度检查无横向溢出。

已人工查看新版手机编辑器、桌面模板卡和手机原生详情。目检发现首屏六个 UUID 使主要动作位置过低，最终版将完整身份和摘要收进可展开区，重新执行三档流程并重拍。该调整只影响布局，不改变选择、原请求或资格边界。

真实模型质量、业务资料完整性、正式评分和目标环境长期运行仍需分别验收，不能用这些合成浏览器结果替代。
