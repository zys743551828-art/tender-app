# 整包范围核查前端检查点

日期：2026-10-20。代码分支：`work/bid-workbench-completion-20261021`。

## 已连通的用户流程

- 读取并校验执行准备输入，显式选择已保存的依赖计划，再启动整包范围核查。读历史、保存计划、编辑草稿均不会自动启动。
- 启动前保存原幂等键和完整请求。网络故障、异常回执和幂等冲突保留原请求；原键恢复不改输入、计划或摘要。当前方法最多核查 400 条要求，超过时保留计划及草稿并明确显示尚未启动。
- 读取服务端真实任务状态，轮询当前运行，取消时使用实际 operation 身份及原 If-Match 条件。取消受理后重读运行，不把取消请求直接展示成已取消。
- 报告按真实五类结论显示，要求列表每页最多 20 条。逐条矩阵完成与整体覆盖区分；整体覆盖始终为部分，清单完整性、正式评分和投递资格始终为否。
- 逐条原引用打开前核对证据、文件版本、解析身份、物理页及原件摘要。历史撤回或已变更的来源说明其当前状态，不恢复旧资料资格。
- 显式读取本次保留的执行 Input，校验完整摘要及原冻结、准备、计划、方法身份。原计划按编号与摘要读取；事实原适用声明按 Input 中的事实、声明编号及摘要读取。输入依据与完整范围核查结果均可导出 JSON。
- 执行结束后，用户填写理由并显式生成带复检身份的新准备输入；再选择计划启动新一轮。复检准备丢失 ACK 后可恢复原 nonce、理由和幂等键。
- 逐项人工意见使用独立记录：确认此项判断、不采用此项判断、需要复查。原始机器 matrix 不改写，人工意见不表示风险已解决或获得投递资格。
- 人工记录绑定原报告、条款摘要和当前 head。CAS 冲突后重新读取当前状态、保留草稿，由用户再次决定。只可选择原机器行已有的完整引用，理由必填，允许不另选引用。
- 人工 Current 使用轻摘要；详细历史与引用按单行分页读取。原 POST ACK 单独显示，恢复到旧 ACK 后重读 Current，避免把旧回执误当最新意见。
- 人工草稿跨报告翻页、筛选和页面重载保留；待恢复请求保持原键、原 body、原版本条件及原引用。新增恢复记录使用现有账户清理注册表。
- 两轮核查对比使用同一标段中用户明确选择的两条已完成运行，按精确要求编号及定义摘要匹配，独立呈现定义变化、机器行／判定变化和每侧人工意见。分页每页 20 条，完整读完后核对总条数和完整对比摘要；人工快照变化导致游标失效时，暂停续页并要求重新读取。
- 对比的每一侧都可读取自己的原冻结输入、执行准备与完整运行，按原引用定位，不影响当前计划选择。相同内容已有核查时，明确拒绝新启动并清除本次未受理请求，提供原运行入口；不会把旧准备下的运行当作新准备的成功回执。
- 对比单项可直接打开该侧原条款，额外核对指定要求编号和原机器行摘要后定位。原报告支持编号／要求内容检索；检索只影响界面展示，完整 JSON 和报告导出不截断。找不到原条款或行摘要不符时，不展示其他条款替代。
- Word／PDF 报告副本先读取当前生成依据，再由用户明确申请，固定原结果和当时人工意见。无 PDF 转换能力时只提供 Word。人工意见或报告方法变化时，拒绝旧依据的新申请，要求重新读取并再次决定；不会自动改用新依据发送。
- 报告申请与取消均保存原 key、body 和取消状态版本。原 ACK 与实际生成终态分开处理，取消后重读报告。历史副本按原运行读取，报告失败或取消可明确重试，不重跑模型核查。
- 下载前核对文档及授权的 `review_report` 用途、原文档编号、标段、媒体格式、字节数与摘要；实际取回字节再次核对 SHA-256。错误用途、其他版本、损坏字节和卸载后的迟到下载均不会触发下载。

## 证据边界

本检查点验证 React 交互、协议绑定、原请求恢复与受控并发行为；测试使用标明合成内容的 fixture 和模拟 HTTP 回应。它不证明真实模型判定质量、真实私有原件效果或实际浏览器 PDF 渲染效果。正式范围完整性与评分资格未开放，界面未将其展示为可用。

Word／PDF 导出使用独立报告接口和异步转换记录。测试中的下载字节明确为合成数据，仅证明身份、完整性和恢复机制；实际 DOCX／PDF 排版与服务端渲染由独立端到端验收确认。报告副本、JSON 和两轮对比均不作为投递标书资格证明。
