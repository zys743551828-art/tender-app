## 已完成的工作

本批接通「明确选择同一包修订的实交与官方结果 → 核对独立证明 → 保存历史准入 → 明确选择研究用途 → 冻结 CPU 协议和研究组 → 创建或控制任务 → 读取原结果」的用户操作界面。既有 CPU 执行继续由独立凭据的工作进程完成；界面登记 queued 任务后明确等待独立执行，不自动运行模型。

主计划依据仍是 `tender-docs@13bfcf194f997c68216179bec72ab657d517d734` 的 120 项 F00—F14。原主记录在本环境实际找到于 `/workspace/scratch/ff42522b09df/tender-docs`，按确切提交读取，没有修改冻结规范。本批推进 F06-06/07/08、F12 和 F14-04 的软件操作与验证切片，不关闭全部工作包。

### 项目内准入

- 在项目的已保存技术范围中，切到「历史样本条件」，明确读取并选择实交和官方成绩；不默认选择最新项。
- 读取严格准入依据后，核对原范围、实交、标签知悉时点、官方技术分、满分和独立核验回执。真实零分保留；未知值不替代为零。
- 明确选定证明、填写原因、勾选确认后，使用原上下文 ETag 和独立幂等键保存。客户端不能签发证明、切换测试权限或免除服务端来源核验。
- 原生上下文可能同时返回已核验的合成证明与「外部真实证明适配器未配置」。界面保留提示，仅允许在明确选择已有 synthetic proof 时进行合成机制路径；其他 blocker 继续阻断，普通 API 仍拒绝 synthetic 新准入。
- 切换检查用途保留明确选择的历史元数据和未发送表单；用途专属的量尺和条件结果失效。非历史用途下不能发起新准入。未确认原请求始终可以恢复，明确清空未发送输入不产生业务写入。
- 接入既有项目导航守卫，报告真实 busy/pending/dirty；未发送输入受刷新离开保护。只有有效 ACK 核对完成后才清除原请求和已发送输入。

### 全局研究工作面

「评分研究」默认打开「整包历史研究」，旧单稿研究记录保留独立入口。

| 步骤     | 用户操作及结果                                                                              | 必须保持的条件                                                                                    |
| -------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 选择资料 | 明确读取目录、打开详情，逐份选择已准入资料                                                  | 目录本身不授新用途；详情须摘要匹配且当前有效                                                      |
| 冻结方案 | 选择已有 CPU 协议，或读取实际方法并冻结新协议；为每条资料明确指定拟合、开发、校准或最终用途 | 至少两个独立拟合组、开发组和最终组；服务端按完整关联闭包复核，不能混合 synthetic 与 external 来源 |
| 固定时点 | 输入实交分界与标签可用截止；可使用带时区的精确输入保留六位微秒                              | 原字符串发送，不舍入，不回填原实交或训练冻结时点                                                  |
| 登记任务 | 明确创建 train 或 evaluate，保存原请求                                                      | cohort-view ETag；同组同类任务复用原记录；queued 不表示完成                                       |
| 控制任务 | 明确暂停、恢复或取消                                                                        | job-view ETag 和 generation；412 后重新核对，来源失效不能恢复执行                                 |
| 读取结果 | 独立读取原训练或评估结果，展开依据和版本身份                                                | 不重新训练、不曝光新的最终集、不改写历史、不授正式资格                                            |

三个步骤保持挂载，切换步骤保留未发送输入。任务控制被明确拒绝后保留原因、清除确认，并要求重新读取；成功读取新的任务状态后清除旧控制动作，避免旧 pause 意图留在新的 paused 状态。

结果呈现包括总分母、成功/失败/拒绝/未标注、独立关联组、项目等权和样本误差、原量尺误差、P90、±3 分比例、偏差、区间、配对基线和分层统计。不存在的标签或区间显示「未取得」。选中数量、排除数量和最终一侧候选不是互斥分区，不能简单相加。合成原生示例为选中 6、排除 2、最终一侧 3，其中成功 1、拒绝 1、未标注 1；这些数值只检查统计口径。

### 本批修复的实际缺口

1. **原协议 ACK 恢复受当前方法版本干扰。** 原实现先构造当前 CPU 协议并核验 method digest，再检查原请求回执；方法更新后原键无法恢复已成功的结果。现在保持当前鉴权、公开安装守卫、读取依赖与原请求绑定，先恢复已存在的原 ACK，只有新命令才构造并检查当前方法。新键仍返回 `PACKAGE_HISTORY_METHOD_CHANGED`，不增加持久记录。
2. **成功回包需要额外语义绑定。** 在实际 OpenAPI 生成的运行时 schema、摘要和 ETag 校验之外，评估 timing 必须等于原研究组；已有 context digest 的准入上下文必须保留三时点、官方技术分和满分。对重新包装且重新计算摘要的错误响应也拒绝清除 pending。
3. **项目内切换用途可能静默丢稿。** 父组件先前卸载准入组件并清空选择，导致未发送原因和证明丢失。现在持续按成员/确切范围挂载，保留选择、输入及恢复入口，并接入项目守卫。已有只读条件检查依旧按目的失效。
4. **浏览器布局。** 补齐新工作面的内边距、窄屏布局和显式复选框方向/尺寸，修正全局 label 样式继承导致的确认区排版。

## 契约、权限与恢复

本批没有新增后端路由、DDL 或目标契约。生成器从实际 `fusion-implemented.openapi.json.gz` 增加前端需要的 18 个 schema 根及引用闭包，并生成运行时 schema。真实应用重新导出后与原 gzip 快照逐字节一致；TypeScript 和运行时 schema 临时重生成后也逐字节一致。

恢复记录按成员和工作面隔离，准入使用 `admission:<bidId>:<scopeId>`，全局研究使用 `research`。保存前先记录原 path/body/ETag/key 和预期身份；存储失败不发送。未知网络结果、错误成功回包、401/403 和无法确认的重复命令均保留原请求。只允许核对同一原请求，不允许换键绕过。命名空间已加入既有退出/成员切换清理。

历史读取和恢复仍依赖当前读取权限、公开安装守卫和原始依赖完整。来源后来失效不会重写原 ACK、快照和结果；新的准入、研究任务或恢复执行仍检查当前来源与权限。不能把本次「证明撤回但读取依赖仍在」测试推广为任意撤权后都可以读取。

现有研究 SQL 仍为可选扩展；本次没有加入 BASE、默认 Fusion v14 或其恢复清单。安装与角色详见 [原生验收](package-history-ui-native-acceptance.md)。初始化 owner 只用于全新数据库与授权引导；API、普通 API、证明核验、CPU train 和 CPU evaluate 使用独立非 owner 凭据，未放宽用途和标签权限。
