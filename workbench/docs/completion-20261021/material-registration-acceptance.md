# 原生待核验材料登记验收

独立登记端口以服务器实际时间／LOGIN／随机 ID 写入不可变待核验记录，引用完整 context、恢复清单、原观察和方法摘要。先将完整命令固定至私有 CAS，再拥有独立写事务；写入结果不确定时，关闭重开后可按固定命令和 packet 摘要查询／重放同一原记录。四个独立连接并发同命令实际只创建一份记录。

契约见[待核验登记](../../packages/contracts/package-native-material-registration.md)，权限范围见[权限边界](material-registration-permission-review.md)。可选 SQL 只在显式全新独立 Compose 检查库初始化；登记 LOGIN 仅一组／两 RPC，无表直接读取／写入、其他用途或 owner 继承。函数实际正文／执行元数据与有效权限严格核对，运行时不修复授权。SQL 不进入 BASE 或正常业务库。

最终 **190 项 Linux 71.26 秒**通过：26 项原生登记、26 项登记纯契约、12 项恢复编码、29 项实际文件、16 项归档、14 项编码、35 项图文、20 项端口隔离、12 项 Compose。**123 项 Windows 17.09 秒**为纯契约、图文、三槽与隔离回归，套件有重叠，不相加；五文件格式／lint、一实现 Linux 目标 mypy／bandit 通过。179 项首轮是中间轮次，不累计。

完整合成链路实际取得原件两次、恢复重读两次，再固定命令、关闭重开、独立 LOGIN 登记、模拟丢失写入返回后按固定命令查回原记录及重放原记录。实际 `recorded_by`、原生 ID 和记录摘要相同，context 引用保持。其他登记 LOGIN 即便拥有同一窄能力，也不能读取或重放原 LOGIN 的命令。没有真实供应商调用。

反例覆盖同命令换内容、跨项目／命令／packet／记录摘要、其他用途与 owner 连接、直接登记表／业务／标签读取及直接 UPDATE／DELETE、额外 PUBLIC 权限、实际函数正文改变、借用事务、非法结果提交前回滚、null version、额外资格字段、布尔摘要和零摘要。冻结待核验记录实际 UPDATE 被不可变触发器拒绝；项目关闭后仍可查询原事实，不能因此认为仍有评分资格。所有权、函数和权限反例只由隔离夹具建立／还原，运行时不修改权限。

`status` 固定为 `awaiting_independent_verification`，四项资格由服务器固定 false。`native_record_identity_verified=true` 只表示原生记录及摘要一致；没有正向输入核验或正式 binding。仅向原生 RPC 提交合成摘要引用也只能得到待核验状态，引用形状不证明材料程序执行、必要范围、来源权威或当时存在。独立核验必须重新取对象及证据并追加决定，不修改此记录。

[原始证据及源码回执](evidence/material-registration/receipt.json)固定 11 份脱敏证据和八个修改输入原始 Git 字节；所有既有观察、材料、归档、恢复及 `/2`、`/3`、模型／特征方法不变，旧记录保持。没有公开 HTTP 或前端改动。

本机 5188 为 1217 份运行输入／68 份资源，登录退出和端点边界通过，API／Web／PG 健康。正常业务库登记 schema／核验角色均 0，design 136／BASE 37 保持；独立检查库所有 `fusion_%` 数据库、LOGIN 和四类核验组均 0，检查及渲染停止，正常 Word 保留。业务写入和付费调用为 0；开发源挂载观察不当作不可变发布。
