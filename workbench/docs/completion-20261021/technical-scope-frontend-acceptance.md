# F06 技术范围与条件检查界面验收

日期：2026-10-21。当前基线 `65433caebe5385c4bb0c6546fe53479c2cdefd86`，后端范围和边界见 [technical-scope-acceptance.md](technical-scope-acceptance.md)。

## 用户可走通的路径

在明确包修订和要求清单后，逐项选择完整技术页段，给全部已识别评分条款选择纳入／排除／未判断并说明理由。读取完整预览，核对所有原件、物理页、原文块、表格结构和缺口，明确确认后保存。修改任何选择即作废原预览与确认。查看历史必须明确选择原记录，分页不截断完整保存内容。

请求在发送前持久登记；响应必须通过原成员／项目／包／清单／请求体／If-Match／幂等键和规范摘要校验才能清除恢复记录。网络失败、坏200、身份中断或迟到回包保留原请求，重新载入可沿用原键恢复。未确认请求参与统一离开保护，退出清理沿用成员边界。

保存或打开历史范围后，新增“当前评分条件／历史样本条件”。当前入口不读取成绩目录；历史入口需明确读取并选择同包修订的实交及可选官方成绩。量尺先检测服务配置再读取目录，无默认选择。响应再次绑定完整范围、来源证据、选择、实交摘要和时间。切换用途或选择立即清除旧结果，其他范围迟到回包无法显示。

官方技术零分保持为0；未取得标签仍未知。可展示匹配冻结招标原文的有据满分，但不据此生成数值估分。历史成绩记载的满分单独标注，不能当作招标分母。研究时间未冻结则保持未知，样本仍为待补、未创建。所有正式资格字段保持false。

## 实际证据

- 范围协议12项、原请求恢复5项、范围UI4项；条件协议4项、目录2项、条件UI5项。前端网络是显式夹具；实际后端行为另批验证。
- 其中使用不修改业务字段的真实非owner PG／ASGI HTTP回执。新增目录联调 `test_package_technical_eligibility_catalog_pg.py` 1项通过（5.01秒），同时读取共享实交目录、成绩目录、未配置量尺能力和所选上下文，核对完整binding摘要与官方零分。合成原件、无模型调用。
- 实际 Chromium：1280／768／390像素，范围选择→预览→模拟服务端已成功但丢回执→刷新→同key/body/If-Match恢复，3档均通过。
- 当前与历史检查分别在上述3档和明暗两主题中操作，共12种状态；均无横向溢出或页面脚本错误，实际显示60分有据满分与官方0分。浏览器回放PG导出的合成响应，不冒充实时浏览器到数据库验收。
- 已目检手机深色历史检查和桌面浅色当前检查，全文和缺口保持可读。截图和回执摘要见 [technical-theme-browser-receipt.json](technical-theme-browser-receipt.json)。

机器夹具位于 `apps/web/src/test-fixtures/technical-*.json`，包含明确合成材料与真实本地身份，不含账户口令、对象凭据或私有对象键。运行命令：`npx vitest run src/*Technical*.test.*`；浏览器命令需显式本机Playwright及Chromium环境，`node scripts/check-technical-scope-browser.mjs <临时输出目录>`。完整前后端集成回归另记于本检查点总回执。
