# 项目整包目录摘要与同源定位

## 已实现

项目列表和概览从同一个只读批量接口读取整包目录摘要，原列表的单稿历史提示不再充当整包主要状态。摘要显示已登记招标依据包／投标包、当前head的文件成员和解析身份未冻结数量。可打开整包工作面或已结束项目的稿件阶段历史，不自动选择最新包、最新清单或最新核查运行。概览中原单稿入口继续显式折叠保存。

读取每批1—20个不同项目，单个只读REPEATABLE READ事务，批量SQL聚合，不逐项目加载旧单稿核查。缺项目、损坏head、超批次或重复项目拒绝。前端最多两个批请求同时进行；切换、重读或服务器事件使旧响应失效，错误／串项目响应不显示旧摘要或0风险。目录动作和实际核查资格分开；风险与预测仍未知，三个完整性／评分／提交资格保持false。完整协议见[项目摘要](../../packages/contracts/project-work-summary.md)。

- 固定Compose检查组最终**19项通过，11.90秒**：14纯协议／投影与5个真实非owner API场景。包含两类包准确计数、相同原件在另一包登记为独立成员、真实未选择解析的成员计数、批次顺序／重复／上限／缺失、会话、零业务写入及原项目ETag不变。存在一条既有Starlette／AnyIO弃用警告，不是跳过。
- 完整前端**177文件／1742项通过，236.83秒**；新增11项覆盖未知不得归零／转绿、跨项目响应、晚到响应、重读失败、导航和61项目有界批读取。清理失效请求的回调整理后又单独复跑11项通过，1.70秒。28项首次针对性组合与11项均与全量重叠，不相加。
- 实际OpenAPI／生成／部分路由契约**12项通过，5.35秒**；同一改动提交确定性gzip实际快照、生成器与生成类型。Python Ruff、格式、mypy与Bandit，前端格式、ESLint、TypeScript及生产构建通过。

初次纯前端组合有26通过／2失败，原因是测试beforeEach错误返回mock函数，被当作清理回调；修正测试钩子后28项通过。初次契约有5通过／7失败，原因是新扩展在未注册此路由的部分应用中直接取路径；改为只扩展实际注册路径后12项通过。新增未冻结解析反例先18通过／1失败：夹具错误传入null，而既有创建协议要求省略未选择的解析字段；修正夹具后19项通过，没有放宽协议。初次ESLint有一条失效引用清理警告，改为明确失效回调后无警告。
