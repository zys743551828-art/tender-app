# 章节树折叠、直接移动与确认后继续编辑

日期：2026-11-12。范围仅为 FR-037 的章节树交互及其保存边界，不代表整个需求、真实复杂标书往返或业务签收完成。

## 需求与实现

依据产品 PRD §10.5 的可展开章节树、鼠标与键盘等价移动、影响预览和可恢复修订，以及 F07-01 的最多六级、500 节点约束。本轮只读核对主需求文档，没有修改主需求仓库或用户改稿。

- 章节树可以逐级收起，当前编辑章节的祖先保持展开；只保存本成员、本标书、本草稿的折叠状态，不保存正文。
- 鼠标拖动“移动”手柄到目标章节；键盘和窄屏可在相同表单选择来源、目标、之前／之后／作为子章节。两者都只创建预览，明确确认前不改变目录或正文。
- 预览前先等待当前正文保存回执，再读取同草稿、同修订、同快照、同 ETag 的最新目录。正文保存导致的修订变化可以继续；目录拓扑、标题、草稿身份或权限漂移则停止，不能把旧手势重新解释到新目录。
- 在新目录上重新计算去掉来源后的目标序号；拒绝自移、移入后代、无效层级、超限和无变化。不信任外部拖入的 DataTransfer 数据。最终仍由既有服务器预览、CAS 确认、历史及修订机制裁决。
- 新确认前再次检查保存／本地恢复；重试不确定回执时仍查询原请求，不换原 ETag，不重做用户意图。412、只读、卸载和作用域变化均保留安全边界。

## 已复现并修正的继续编辑缺陷

实际 Panel + SectionEditor 测试先复现：目录确认已应用到草稿修订 3，但同一章编辑器仍持修订 2 的保存头，继续保存必然冲突。

修正仅在取得结构 applied 回执后，核对服务器草稿及快照，并确认前后仍是同一个、已保存且无本地恢复／章节操作中的编辑器，才重新读取外层正文加载器。拒绝、412 和单纯折叠不会重新挂载。读取失败或服务器又有更新时，保留旧正文与本地副本，阻止后续改写，提供明确的 GET 重读入口，不重发结构操作。未知恢复副本不会被清除，也不会绕过 flush(true) 进入结构写入。
