# 本地真实检索与分档容量验收（F09-06／07）

本轮已接通并实测 PG17／pgvector、真实离线 BGE 向量、Jieba／PostgreSQL FTS、独立编号数字召回、RRF 和可选真实重排。企业知识同时走发布、实际索引、适用范围检索、引用和撤回链。本文记录的是软件机制与单机合成容量；真实企业资料相关性、正式评分资格和目标部署 SLA 仍未验收。

最终机器收据为 [local-retrieval-receipt.json](local-retrieval-receipt.json)。收据绑定执行前的相关源码 SHA256、实际初始化 SQL 及其顺序，并确认执行结束后源码没有变化。原始失败尝试和早期容量数据不混入该最终结果。模型付费调用数为 **0**。

## 本次改动与行为

### 编号、数字与既有向量／全文召回融合

新增 `packages/rag/numeric.py`，普通文档和企业知识共用。查询含可识别编号／数字时，每个通道各提供最多 50 个候选，按 RRF（k=60）融合；最多 20 个融合候选进入重排，最多返回 8 个证据包。向量通道继续使用授权范围内精确 cosine 距离排序。数据库已有 HNSW 和 FTS GIN 索引，但本次容量数字是生产精确 SQL 路径的实测，不是 ANN 压测结论。

数字通道使用 NFKC 查询规范化、大小写无关匹配、ASCII 标识边界和绑定 SQL 参数。验证了 `C30` 不匹配 `C300`、`3.2` 不匹配 `3.20`、标准年份不混用以及正负号和单位后缀。原文、摘录、证据块和物理页不被改写。单次最多 32 个不同标识、单项最多 64 字符，超限返回明确错误，不静默截断。该通道是字面召回，不做单位换算，也不判断条款含义；不覆盖任意自然语言数字表达式。

三路查询使用同一个已授权集合。普通文档继承来源、用途、时点、排除组及排除证据过滤；企业知识继承已发布版本、主体、工程适用条件、用途、时点和祖先来源范围。查询后、结果应用和知识引用时继续核对当前资格；重放原请求也不能使已撤回来源重新可用。空结果只报告查证范围不足，不等于没有要求。

修复了普通文档重排的一个边界：有分数但缺少真实模型身份时，原先可能按分数排序并记为成功。现在只有分数完整、有限且返回实际模型身份才采用重排顺序；异常或缺少身份保留原 RRF 顺序，并记录 `reranker_unavailable`。企业知识沿用已有的严格重排身份检查。

### 运行方式与持久证据

新增 `deploy.rag_native_acceptance` 和 `deploy.rag_native_scale`。运行器要求明确给出 PG 二进制、模型 Python 和已核验资产目录；每次创建新的临时 PG 集群、数据库、不同非 owner API／Worker 登录及随机 loopback 端口。模型进程只接收模型配置，不接收数据库口令。业务访问权限由原空库 bootstrap 验证，测试没有改用 owner 绕过业务权限。

原件读取、分词、向量和重排在业务数据库连接关闭后执行；发布和采用时在短事务内重新核验来源。成功后停止本次模型和 PG 进程、清理本次临时数据和运行配置。失败仅保留私有诊断；终端和提交收据不含数据库口令或真实私有原件。

### 这些数字测了什么

每档建立独立项目、parse、来源和证据 ID，分别核对 `eligible_chunks` 和已存向量数严格等于 1,000／10,000／50,000。查询覆盖完整授权范围，没有把 50k 先截成 5k。三档在同一新临时数据库中顺序建立，已有小档数据不会冒充当前档的授权数量。

为限制本机内存和模型计算时间，容量夹具有 **128 种不同合成条款**。128 种文本先真实执行 BGE embedding，重复文本复用相同的真实模型输出；数据库内每条证据和物理页身份独立。这验证了相应行数上的过滤和 SQL 检索，不测 50k 不同文本的模型推理成本，也不证明真实标书的内容分布或召回相关性。

每档 4 个查询、各执行 3 次，SQL 统计含新建连接及查询，不含查询 embedding、重排、浏览器与网络链路。每档第一次的 4 个查询另测真实 CPU top20 重排，并对 top8 核对原文和物理页。P95 使用 nearest-rank；12 个 SQL 样本与 4 个重排样本都不足以建立生产 SLA，当前 P95 实际等于各自样本最大值。不能把 SQL P95 宣称为端到端用户延迟。

各档的 4 个合成编号目标都进入 top8，所有返回摘录／物理页与本次独立生成的证据表逐项一致。这是可重现的字面目标及引用校验，不是工程师标注的真实业务相关性评测。

### 企业知识容量边界

普通文档的 50k 实测不扩大企业知识的现有上限。企业知识仍限一次 500 个已发布适用版本和 5,000 个通过逐单元来源完整性核验的单元；超过上限返回范围过大，不少报成成功。

该 5k 上限当前属于授权范围构建和逐单元不可变出处核验，不只是 RRF 前候选数量。直接删除限制或先任取 5k 再排名会破坏范围语义。本轮保留守卫；若需扩容，后续须将完整范围身份和权限核验改为有版本的 SQL 预过滤／分页快照，并验证未遍历全部范围时不能发布“完整范围”结果。当前没有用普通文档容量结果宣称企业知识 50k 已通过。

## 复现

准备 PG17 安装，包含 `vector` 和当前基础结构需要的 `uuid-ossp`；应用 Python 安装主依赖及 `requirements-fusion-checks.txt`，独立模型 Python 按 `requirements-rag.lock.txt` 安装 CPU 依赖。模型目录包含 `dense` 和 `reranker` 的已验证资产。然后从 `workbench` 运行：

```sh
/absolute/app-venv/bin/python -m deploy.rag_native_acceptance \
  --pg-bin /absolute/pg17/bin \
  --model-python /absolute/model-venv/bin/python \
  --assets /absolute/verified-assets \
  --receipt /absolute/new-local-retrieval-receipt.json \
  --scales 1000 10000 50000 --unique-texts 128
```

收据路径必须不存在，避免覆盖历史证据。省略 `--scales` 可只运行真实链路检查；三档规模可分别显式选择，不自动把未执行档记作通过。本入口只启动本次私有本地进程，不把该模型或新检索路径部署到生产。
