# 固定整包正文采纳、构建与明确入包前端验收（B3/B4）

本批接通固定整包候选的明确采纳、采用后的精确正文读取、固定修订文件生成与明确入包。用户可核对完整原稿和拟稿后采纳，读取服务端保存的正文修订及来源资格，再单独生成文件和选择目标投标包。候选发布、正文采纳、文件生成和文件入包分别显示实际结果。

本记录是前端专项证据。B1 采集、B2 原生候选生成、B3/B4 数据库与对象存储验收、全量前后端回归由各自收据记录；本记录不将浏览器中的响应重放计为原生数据库执行。

## 已接通的用户流程

| 环节           | 当前行为                                                              | 关键约束                                                                                                |
| -------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 核对候选       | 读取原输入，显示完整原稿、完整拟稿及文字增删；另读当前采纳能力        | 原输入、完整章节、目标节点、候选身份与原 ETag 必须相符。B2 已保存运行的历史能力标志保持原值             |
| 明确采纳       | 用户勾选已核对全文后，使用原操作卡的确认入口追加正文修订              | 勾选前不发送命令；候选、能力或输入不可核验时不开放新采纳。拒绝和原请求恢复仍独立处理                    |
| 核对保存结果   | 显示服务端 `draft_id`、修订、快照与摘要，再交叉核验快照正文和来源资格 | 回执、原输入、完整拟稿、快照扩展、章节修订与 qualification 必须一致，才提供这份正文的后续入口           |
| 查看采用后草稿 | 从真实快照扩展识别固定来源修订，并读取当前资格状态                    | 普通编辑、目录修改、新导入和新生成受限制；章节导航、原稿与历史读取仍可使用                              |
| 生成文件       | 发送已选择草稿修订对应的既有构建请求                                  | 若重新读取发现修订或快照改变，停止新构建并保留选择；不自动切换最新版。固定整包构建使用 `follow_up=none` |
| 明确入包       | 按成功格式选择文件、目标投标包、用途及解析范围，再单独确认            | 文件生成完成不自动入包、不自动核查；采用回执保存精确草稿与快照身份                                      |

固定快照尚未附加目录或自定义版式时，前端发送服务端支持的内置正文模板请求，并明确说明暂不提供章节排版选择。存在固定目录与版式时保留原双模板行为。修复前旧界面会给普通固定快照附带目录／版式参数，导致真实 API 返回 `BUILD_TEMPLATE_SNAPSHOT_MISMATCH`；本批使用未经改写的原生 B4 请求验证了修正后的请求形状。

Word 和 PDF 分别显示结果。本次原生 B4 样本中 Word 成功，PDF 因转换器未配置返回 `RENDERER_UNAVAILABLE`；界面如实显示 PDF 失败，同时允许单独核对、下载和采用成功的 Word。未配置的能力仍不可用，保存或生成成功均不表示内容通过。

## 身份校验与原请求恢复

`authoringExactProtocol.ts` 对可计算的输入、候选、回执、快照扩展和来源资格使用闭合协议与摘要校验。采纳后必须能证明保存的正文对应原候选的完整拟稿，保存的草稿对应原输入目标，来源资格对应同一 action、job、input、章节与修订。响应结构合法但属于另一草稿，也不能清除本地未决请求。

操作卡发送前持久化原成员、原候选、原目标草稿、ETag、决定和幂等键。丢失 ACK、未知错误、鉴权失败或不匹配的成功响应均保留原请求；刷新后的恢复继续发送原正文、原条件头和原键。已知修订冲突转为明确冲突状态，用户重新读取候选后须重新核对，界面不会静默生成替代确认。另一个成员已经处理时，显示服务端实际返回的终态，不推断本成员的意图已经生效。

旧 B2 保存的未决操作记录仍可恢复。注销后迟到响应不能重建已经清理的记录。存储不可读或记录不可信时停止新写入，保留可读信息。

草稿只读守卫区分“创建新写入”与“恢复已经发送的原请求”。既有章节 PATCH、结构操作和编写方案请求可使用原键恢复；未发送的本地文字继续保留，不能借“重试”创建新 PATCH。明确拒绝的原保存请求清理后，也不能再次生成替代写入。针对这三类边界有专门组件回归。

## 普通草稿与固定来源草稿的区别

前端先读取真实保存快照。快照没有 `authoring_exact_sections` 扩展时，沿用普通草稿编辑行为，不要求部署可选的 exact SQL，也不读取缺失的 exact 资格表。含该扩展时，核验扩展及当前资格状态；读取失败、身份不一致或能力缺失均阻止相关新写入与构建。

只读提示不会使章节导航一并失效。历史快照和来源信息继续可读；读取历史本身不授予执行资格。后端在新采纳、构建和入包时仍独立复核当时的来源、事实与权限，前端的历史身份核验不能替代服务端执行判定。

## 保留的产品边界

含固定整包来源的草稿当前禁止普通编辑；后续如需编辑，应新增后端认可的来源与修订协议，不能仅解除按钮禁用。无目录／版式的固定快照使用内置正文模板，不声称已支持自定义排版。未配置 PDF 转换器时 PDF 真实不可用。

这些验收证明的是固定身份、恢复行为、实际请求契约及界面状态一致性。真实模型效果、真实私有投标资料质量、外部 PDF 转换效果、最终投标内容与投标提交仍需各自验收，均未由合成原件或浏览器响应重放代替。
