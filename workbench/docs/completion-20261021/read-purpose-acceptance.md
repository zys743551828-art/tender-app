# 独立核验端口共用只读权限审计

来源与当前范围端口复用纯`read_purpose`审计器。固定实现策略分别声明唯一能力组、可读表列和允许的窄接口；模块只检查实际PUBLIC／继承权限，不加载业务配置、不建连接、不切角色或修复授权。原错误码和观察结构保持，各端口继续负责原生事实与方法身份。当前范围RPC还拒绝核验LOGIN通过所属角色继承接口所有权，不能只检查owner是否等于LOGIN名称。

最终Linux Compose76项通过（46.57秒）：37来源PG、21范围PG／真实API、6隔离导入／错误兼容、12编排；Windows6项2.28秒通过，范围重叠。六文件Ruff／format、四实现mypy／Bandit通过。继承组拥有RPC时原生正文检查拒绝；新包、依据包与清单追加、撤回、越权表列、额外definer、循环和容量拒绝等原反例保持通过。来源／范围事实读取执行体AST与原生SQL不变，观察方法明确绑定共用源码而换新摘要；旧回执不改。原页、输入、序列化、判断与特征方法保持原值。

初次组合57通过／1失败：继承所有权拒绝已生效，但合成测试把owner改回后，PG合并ACL使原能力组的显式执行grant丢失，测试恢复步骤不完整。只在独立检查库由初始化owner恢复测试改变的ACL后，最终76项通过；运行时仍不修复权限。原失败、最终结果、两个原生合成观察及方法比较见[证据回执](evidence/read-purpose/receipt.json)。

5188为1191运行输入／68资源逐字节匹配，登录／会话／退出与错误响应通过，三服务健康，业务项目／付费0。检查库、临时LOGIN和本批两种能力组0，checks／检查PG／renderer停止；正常Word与其他环境保留。无HTTP、SQL或前端变化，浏览器缺模块、真实配对暂无的缺口保留。接着做受控对象字节、必要范围及独立原生核验回执；这套审计不是新账号平台，也不授正式执行资格。
