# 固定来源文字修订后主正文显示同步

日期：2026-11-12。范围只修正已校验文字修订回执之后的可见正文更新，不放宽固定来源资格、普通编辑、构建或来源链协议。

## 真实组件反例

在本机合成 HTTP 中使用已有 native ExactText fixture 的完整身份、qualification、原请求、ETag 和回执，不重写资格摘要：实际 Panel 明确提交单节点文字替换后，保存头和来源资格均更新到草稿 3，专用修改入口再次就绪，但主“章节正文”仍显示旧文字。外层 SectionEditor 虽已重读 section，同一 SectionBody 的初始 value/head/ack 不会因此更新。

普通编辑始终被固定来源资格限制为只读，所以不把这个显示缺陷说成普通保存必然 412，也不据此推断导出文件错误。

## 修正与保护

- hook 继续先完整校验文字修订 ACK、原稿、来源链、scope、摘要和保存令牌，再传递真实单节点／多节点回执。父层再次核对项目／草稿、协议、正安全整数修订与快照 ID，不制造新成功状态。
- 仅已保存、无本地恢复／章节操作、前后仍是同实例的编辑器可以按已确认 head 重新读取。来源刷新及 snapshot-change 通知保持，放在末次 clean 检查前；显式 GET 恢复也会重新刷新来源，而不是重发文字修订 POST。
- head 读取失败保留旧正文、本地副本和同步标记，恢复说明可见；来源资格读取失败不等同资格验证通过，仍由现有 snapshot／revision／绑定核验保持普通编辑只读及构建阻断。
- 无参数冲突读取沿用原语义，不把普通读取伪装成新文字修订成功，不自动覆盖未处理输入。
