## 保留失败与处理

首轮为53通过／1夹具setup错误：遗漏原测试类的固定原件参数，冻结被拒；补齐相同合成原件选择。其后56通过／1失败，发现旧规则夹具缺少普通RuleView要求的scope字段。更新既有规则的尝试被append-only守卫拒绝（53通过／1setup错误），未关闭守卫或改owner权限；改为将公共初始夹具提取为可参数化构造器，新案例在首次INSERT时给完整范围，原默认行为保留。随后普通决定请求遗漏必填evidence_ids，再现56通过／1失败；按既有协议补齐空列表后58通过，补最终去重与缺失反例后62通过。

Windows首轮类型检查还暴露.ts／.tsx文件基名只有大小写差异的导入歧义，验证器改名为packageNextActionsProtocol.ts；嵌套回调补明确类型收窄，TypeScript通过。无协议放宽、历史结果改写、owner运行回退或付费模型重试。早期原本地日志保留，正向原始证据另行归档。
