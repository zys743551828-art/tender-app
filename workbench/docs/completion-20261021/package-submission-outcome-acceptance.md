# 整包实交登记、官方成绩与共享统计验收

本检查点在 `work/bid-workbench-completion-20261021` 上，接续已发布的条款修订与历史导入提交 `1bb2e37cfb5efe80e593b64709183e17024a5c18`。它实现完整包的实际提交事实及其官方结果关联，并将两者接入已有的提交历史、业务阶段结果和指标。软件机制验收与正式投递资格、模型准确率分别记录。

## 实际可用路径

在项目提交工作面明确选择投标包、不可变修订及可选的需求清单、范围声明和整包核查运行，读取四类检查。完整性或风险条件没有证据时，标准登记保持不可用。用户可以据实补录已经发生的线下提交，填写准确时间、原因与本项目附件；保存时服务端实际读取并校验原件字节，而目录中的文件名、长度和摘要本身不冒充字节核验。

保存后，原包、原始身份、登记时身份、所选清单、核查结果、检查观察、声明附件及原件摘要固定在不可变 binding 中。登记时间与用户声明的提交时间分开。线下事实不宣称交易平台已经验证、不补造事前系统检查，也不重新打开关闭或归档的项目。

整包和既有单正文共享 `submission_records`、`submission_heads` 和历史列表。更正只追加记录：支持整包到整包、旧单正文到整包；旧单正文入口不能把整包事实降级为单正文。原命令键、原体和原版本条件重放原回执，当前头变化不产生第二条登记。

每条整包记录新增官方成绩工作面：登记技术总分、综合总分或未知，选择准确官方原件并填写取得时间；更正后新记录回到待核验。零分保留为零，未知为 `null`，十进制不经浮点转换。极小数或小数零分的数据库 Decimal 投影改为普通十进制，避免合法成功回执变成指数文本后被界面拒绝。

人工核验固定原实交的工程、标段、轮次、主体、包修订、身份摘要和原招标依据包。确认通过需要对应官方原件的物理页、逐字引文、公布时间及聚合方式，服务端核验时间顺序、来源用途、祖先链与当前有效性。长证据块可完整阅读并选择最多 4,000 字的连续摘录；不能改写或拼接原文，不会静默截断整块。

核验历史与当前可用性分别返回。后续原件撤回或原身份／依据失效时，原 `verification="verified"` 和原凭据保留，`package_association.available` 变为 false。当前统计重新读取有效性，不以原成功状态维持可用。整包正式研究样本仍被明确拒绝，未生成伪造的正文版本、训练样本或事前预测。

## 四类检查与共享消费者

| 检查或消费者       | 实际行为与边界                                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------------ |
| 当前输入与来源     | 核对确切包、身份、成员、解析、来源时效和当前指针；只读预览明确未读取原件字节，保存阶段再做实际 IO 与最终检查 |
| 已知核心要求覆盖   | 统计已声明范围和成功原生运行的逐条判断；需求清单语义完整性与模型质量没有证据时保持 unknown／partial          |
| 核心条款逐项确认   | 使用原清单、原行和原生人工记录；人工不采用不等于原条款消失或风险解决                                         |
| 全项目已知阻断风险 | 跨包及历史记录核查；更换当前包、撤销条款或驳回机器意见不会自动抹去已知关键风险                               |
| 业务阶段结果       | 沿用同一个实际提交 ID；原身份未确认时拒绝新登记，来源撤回后退出当前可用统计                                  |
| 旧正文风险快照     | 整包不会调用旧正文的 current risk 计算，也不会把登记时观察回填成历史实交时风险                               |
| 评分误差           | 没有合格的整包事前预测生产者，返回 `package_prediction_producer_unavailable`；不借用旧正文预测制造有效配对   |

当前 `standard` 的正向完整资格尚未成立。四门协议没有把 `allowed`、`inventory_complete`、`submission_eligible`、`formal_scoring_eligible` 或 `publication_authorized` 改为 true。这是当前能力边界，不能将线下事实登记通过解释为 F05 全部完成或正式可投递。

## 接口、事务和数据库

新增路径均纳入实际 OpenAPI、确定性 gzip 快照和生成的 TypeScript：

- `POST /api/v1/bids/{bid_id}/packages/{package_id}/revisions/{revision_id}/submission-preview`
- `POST /api/v1/bids/{bid_id}/packages/{package_id}/revisions/{revision_id}/submissions`
- `POST /api/v1/submissions/{submission_id}/package-corrections`

共享成绩接口继续使用 `/bids/{bid_id}/outcomes`、`/outcomes/{outcome_id}`、`/corrections` 和 `/verification`。新的整包核验与旧单正文核验使用明确的联合协议。成绩更正使用 `Outcome-Head-ETag`，核验使用该成绩的 `ETag`，两种版本条件不能混用。

原件 IO 在数据库事务外进行。新写入最终在 read committed 事务中重新验证认证成员、当前版本、原件元数据、来源和统一头。原命令重放优先；新事实、原包 binding、head、审计及命令回执原子提交。SQL 约束拒绝缺失 binding、错项目、伪造标准放行、错误回执或不一致 head，失败不留下半条提交。

新 SQL 为 `packages/contracts/sql/bid-package-submissions.sql`，SHA-256 `d6fea7f77da4378e23fae217737ac7cffc38f30255d1bd39885852bc0aaf2b0c`。它位于当前 `BASE_SQL` 最后。Fusion API 预览提升至 v12，使用新的数据库和配置卷，保留 v11 及更早卷；不自动迁移旧预览数据。

### 浏览器和真实响应

[浏览器回执](package-submission-outcome-browser-receipt.json) 保存三档视口、33 张截图摘要和原请求恢复结果。仓库另保留可直接查看的 [桌面四门检查](screenshots/f05-submission-gates-1200.png) 与 [手机原页核验](screenshots/f05-official-original-390.png)，均为明确标注的合成技术资料。

整包界面使用实际非 owner PG 服务及合成 Worker 的固定响应，覆盖 1200、768、390 三档宽度的精确选择、四门检查、丢失回执恢复、原件和历史观察，共 15 张图。已注入一次回执丢失，恢复请求的 body、key、ETag 均与原请求一致；仅看服务器历史不会解除未确认操作。

官方成绩使用同一真实合成提交和更正后的同一成绩 ID，采集 pending、verified、withdrawn 三阶段原始 HTTP 响应。客户端实际校验器已接受三个阶段的上下文、列表、详情及登记／更正／核验 ACK；来源撤回后仍保留 verified 历史，同时正确显示当前不可用。浏览器将同一原生证据条目投影为文件证据目录，这一投影与真实路由响应分别标明，不声称浏览器连接了业务数据库。

成绩前端专门覆盖：零与未知、成绩更正、精确原页、缺依据拒绝正向核验、长块摘录及改写拒绝、刷新后原请求恢复、错误作用域或回执、未知 422 不丢恢复、412 后成功新读取再显式采用、跨头拒绝自动覆盖、存储配额失败不发送、损坏恢复阻止新写，以及退出后的迟到 ACK 不重建业务存储。移动端目检修复了确认框受全局表单样式影响而挤压说明文字的问题；几何无溢出检查不能替代人工目检。

已存储的旧单正文科学计数法 ACK 按原样重放，不回写历史。新整包功能此前未发布，无生产整包 ACK 迁移。本次所有新成绩响应及旧数据的 GET／列表投影使用普通十进制。

## 尚未因此完成

这批实现没有证明需求清单完整性、模型判断准确率、交易平台回执真实性、完整正式评分输入或训练资格。历史关键风险尚不能仅靠较晚的一次 satisfied 判断或人工驳回自动解决。完整本地运行 profile、概览到精确包的主导航、任务的整包输入接线、长期运行及目标环境验收继续作为后续工作。

真实官方分数配对、工程师标注与生产环境 RPO／RTO 等外部条件另行验收。没有使用合成数据代替这些证据。
