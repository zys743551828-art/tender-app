# 准确材料原生恢复验收

私有恢复封套保留原取得观察对象与完整 context／页图归档，关闭重开后通过既有三个独立非 owner 原生端口重新核对当前范围、完整来源图、准确解析与全部原件。重新取得的字节用于恢复原 context；新观察另记回执，原 context 的摘要、`input_as_of`、观察时点和解析身份不变。

实现与闭合字段见[恢复契约](../../packages/contracts/package-native-material-recovery.md)。恢复层负责流程编排，存储及归档契约不变；没有新增 SQL／权限／HTTP，未接业务 API 或 Worker 自动恢复。输入／执行／必要范围／历史资格仍 false，不把恢复观察当作原生登记或发送租约。

最终 **146 项 Linux 37.59 秒**通过：9 项原生恢复、12 项封套编码、29 项实际文件后端、16 项归档、14 项编码、35 项完整图文、19 项端口隔离、12 项 Compose。**96 项 Windows 15.12 秒**为恢复／归档纯编码、完整图文、三槽和隔离检查，套件有重叠，不相加。五 Python 文件格式／lint、一实现 Linux 目标 mypy／bandit 通过。

合成原生正向链路初次取得 2 次完整回环 GET，恢复再 2 次；三个连接在 GET 时 idle，恢复结束也 idle。恢复后的 context 规范字节及原观察对象完全相同，新原生观察摘要不同；同一个合成 binding 引用产生完全相同的 `/3` 请求字节和回执。四条规则、三份依据、条件／例外及原排除保留。恢复不重新渲染图页，初次合成渲染只在进程内；不混入独立 Compose 渲染或真实可读性证明。

当前项目关闭、来源撤回、来源 revision 改变在新 GET 前拒绝；首份新原件损坏、末件 GET 期间关闭、取消操作均不返回部分 context。冻结页实际 UPDATE 被原生不可变触发器拒绝，随后恢复仍保持原内容；读取投影故障另用明确测试注入验证，在新 GET 前拒绝。测试未关闭冻结保护。篡改封套、观察引用、原观察对象、固定 context、方法、false→0 等编码反例拒绝，非法保存不写对象。

首轮尝试修改冻结页触发 `immutable_record`；反例修正为验证保护生效，并单独注入读取投影故障。纯夹具缺少 `document_count` 的测试断言已改为追加改变，不放宽恢复实现。[最终与首轮原始证据](evidence/material-recovery/receipt.json)保留 15 份脱敏文件；中间通过轮次不累计。七个修改输入核工作树／Git 原始字节，所有既有来源、材料、归档、`/2`、`/3`、模型及特征方法和旧记录保持。

本机 5188 的 1214 份运行输入／68 份资源、登录退出和端点边界通过，API／Web／PG 健康；研究可选扩展仍明确 503。正常库核验角色 0、design 136／BASE 37 保持；检查库／LOGIN／核验组 0，检查及渲染停止，正常 Word 保留。真实供应商／付费调用与业务写入均为 0。开发源挂载观察不当作不可变发布。
