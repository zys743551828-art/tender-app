# 同源代理动态地址与健康检查验收

## 行为与边界

API重启后容器地址可能改变，固定解析的Nginx上游曾继续访问旧地址，实际业务接口502而Web健康仍为成功。默认与完整配置统一使用Docker内置DNS、共享上游zone及`resolve`，保留原请求路径、查询、正文和各入口容量限制。健康入口实际访问API就绪接口，连接与读取超时分别1秒／3秒；Web检查失败阈值为3次，启动宽限10秒。

实测镜像Nginx为1.30.5，支持所用动态解析；功能要求见[Nginx官方上游文档](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#server)。未降低容器隔离或变更业务账号、SQL及模型配置。

## 实测

- Web进程保持同一启动时间，API从动态地址切换到同一Compose网络的明确空闲地址，约3.063秒恢复；恢复动态地址分配约5.562秒恢复，再实际重启API约3.094秒恢复。最终健康200、匿名业务入口401。断开API期间探针超时，记录为0，不能写成已观察到特定HTTP错误码。见[地址轮换证明](evidence/proxy-dns/ip-rotation-proof.json)。
- 默认配置及完整配置均在现有Nginx执行语法检查通过。完整配置仅证明语法，不记作完整文件运输链重跑。原故障为结构化观察记录，未保留当时原始网络包，不冒称抓包证据。
- 固定Compose `delivery-pure`最终164项通过、11.10秒、0跳过；Ruff／format和测试文件mypy通过。Windows仅运行结构检查5项通过、7项未选；原完整主机尝试受默认临时目录ACL限制的6个setup错误和误选一个POSIX测试的错误均保留，相关执行用例由Linux完整套件覆盖。
- 检查实例非系统数据库和临时LOGIN账号均0，checks及检查PG已停止。默认5188三服务健康，登录／会话／退出与只读接口通过，业务项目／业务写入／付费调用均0。

当前开发挂载包含同时开发的PDF资产候选，运行指纹1170输入／68个JS与CSS资源；本修复仅对四项代理／Compose／测试改动核Git原字节，不将未提交候选或整棵工作树冒称本提交的不可变发布。回执和原始输出见[证据清单](evidence/proxy-dns/receipt.json)。

本修复处理应用自身的同源代理失联。Codex内置浏览器仍在启动时缺少`browser/26.1016.62342/scripts/browser-service.mjs`，本批没有页面截图或视口验收，也不宣称浏览器跨重启问题已解决。
