## 2. HTTP检查入口

`test_api_boundary.py`通过真实HTTP调用被冻结的`/api/v1`接口，使用Python标准库，不启动假服务。运行前由部署配置提供以下环境变量：

- `QA_BASE_URL`：例如`http://127.0.0.1:8000/api/v1`。
- `QA_ORIGIN`：服务端允许的同源站点地址。
- `QA_LOGIN_NAME`、`QA_PASSWORD`：仅供隔离测试的临时成员，从安全环境注入，不写入命令行／结果。
- `QA_APP_REVISION`、`QA_CONTRACT_SHA256`、`QA_CONFIG_SHA256`、`QA_ADAPTER_MODE`：被测源码／构建身份、契约与脱敏配置摘要、明确的真实／测试／未配置适配器类别。
- `QA_RESULT_PATH`：本次结果输出位置；建议写入测试角色的实施证据目录。

```bash
python qa/run_api_boundary.py
```

缺少实际配置时输出`not_ready`且退出2，不会以跳过测试宣布通过。七个黑盒任务覆盖认证、Origin/CSRF、撤销、创建幂等和请求身份冲突；它们不证明持久化重启、Kafka或上传已通过。未明确为同一状态码的“缺幂等键”接受参数错误422或缺前置条件428，必须拒绝且有可定位错误；涉及具体资源If-Match时仍按冻结协议要求428/412，不降低CAS要求。

每次实际执行须补充应用源码／构建身份、契约摘要、部署配置摘要及适配器类别。测试脚本摘要只说明检查来源，不能代替被测应用身份。失败由开发修复后重跑受影响范围；不得改预期去迎合错误实现。

## 3. 验收记录规则

尚未运行的用例标`pending_implementation`／`pending_environment`；实际执行后记录预期、实际、后端对象、输入摘要和环境。真实API、真实PG/Kafka机制、显式测试模型、真实模型效果、真人试用和生产运行分别汇报。口令、Cookie、签名授权及真实投标原文不得写入公开结果或控制台。

测试只使用独立库、topic前缀和合成资料，不删除开发或真实业务数据。进程终止、网络中断和恢复仅作用于隔离测试环境，不为验收添加可在生产使用的绕过接口。
