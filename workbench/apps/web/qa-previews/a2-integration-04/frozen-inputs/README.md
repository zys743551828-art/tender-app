# 投标工作台前端

React、TypeScript、Vite 实现的内部资料工作区。使用实际后端接口，不内置演示项目、风险或分数。当前切片支持登录和会话恢复、项目列表和简建、PDF原件上传与核验、批次确认、文件版本与历史链、解析范围与物理页依据。A1已提供概览、评审与风险、矩阵、规则、事实、处理记录与设置的客户端骨架；是否开放由实际OpenAPI注册操作决定。当前后端尚未注册的工作面明确显示未开放，不提供模拟数据。当前增加人工章节编写、固定快照Word/PDF构建与档案/研究入口。完整评审、正式评分、实交登记和生产交付尚未验收。

## 运行

在本目录执行：

```bash
npm ci
npm run dev
```

默认只监听 `127.0.0.1:5173`，`/api` 同源代理到 `127.0.0.1:8800`。先按项目部署说明启动后端、私有存储及Kafka Worker，并由维护人员创建成员。浏览器不保存密码和CSRF令牌，刷新通过HttpOnly会话恢复。登录过期保留当前页面输入，重新登录不会自动重放写入。

独立验收环境可使用：

```bash
API_PROXY_TARGET=http://127.0.0.1:8801 npm run dev -- --port 5174
```

后端允许的Origin及私有存储CORS需与实际端口一致。项目列表为 `/projects`，详情为 `/bids/:id/materials`。项目首页 `/bids/:id` 恢复有效工作位置，否则有当前轮次时进入评审，无结果进入概览；显式资料和历史轮次链接保持原对象。A1工作区展示客户端已完成的页面，并在未注册接口处说明不可用范围。

## 上传与恢复

当前只接受PDF，单文件上限100 MiB，使用真实私有对象存储的单次PUT授权。授权指向同源应用传输时携带HttpOnly会话，PUT附当前CSRF；指向外域S3时不发送Cookie或CSRF。PDF固定以application/pdf发送，不手设浏览器禁止的Content-Length。先按文件选择用途及独立文件／指定文件的新版本，再上传核验，最后明确确认有效集合。传输成功、核验通过、入库完成和解析完成分别展示；均不表示评审通过。

部分失败需要明确选择仅将核验通过的文件入库；失败补遗不会悄悄略过。412时保留已核验原件，刷新资料包后重新核对；需要变更目标时填写原因并建立新的入库绑定，不自动覆盖最新版本。写入命令按输入及实际ETag保留幂等键，网络重试复用同一命令键。

批次ID保存在浏览器本地以便刷新后恢复，上传命令身份及摘要保存在当前浏览器会话。若刷新时传输尚未完成，可在对应文件行重新选择相同摘要的原文件接续，已核验文件不需重传。新的浏览器没有未完成传输的接续记录，需要重新选择文件；服务端已收到的业务资料仍保留。签名URL过期会重新授权同一上传，暂不提供分片上传。Word请先导出PDF；当前不声称已保存Word原件或已核验两种格式对应关系。

原件查看使用有时限的私有下载授权，由自托管PDF.js绘制真实物理页，与解析文本并排展示。Worker、CMaps、标准字体、WASM及ICC资源在安装／构建时从锁定依赖复制到本地，运行时不访问CDN。页码取PDF真实总页数，包含未提取文本、扫描和空白页。没有可靠坐标时显示整页；扫描／OCR缺口持续显示，不绘制推测高亮。原页绘制失败时持续显示错误并可刷新访问地址，仍可直接下载资料原件。有新版本的资料行提供历史入口，逐版读取真实元数据，历史文件名、原件、解析依据及下载身份分别保留。文件身份只在详情展开，不把摘要塞进日常表格。

## 契约与验证

`src/contracts.ts` 仅生成当前UI消费的schema闭包，来源是根目录 `packages/contracts/implemented.openapi.json` 的实际实现契约。生成类型不表示完整目标系统已实现；本页面只调用当前注册接口。生成文件也包含实际method/path能力列表；目标schema存在不代表对应服务已注册。后端actual契约更新后重新生成才能开放对应工作面。

```bash
npm run contracts:generate
npm run format:check
npm run lint
npm run typecheck
npm run test
npm run build
```

资料查证从工作区“查证资料”按需打开，不挤占风险流程。查询草稿在当前浏览器会话保留，网络重试保留原查询及幂等键；编辑后的查询需要明确重新查证。结果持续显示索引缺口，不把空命中称为不存在要求。引用使用真实文件版本与物理页；打开前复用原请求核对来源，409后明确标记历史，仍可追溯当时原页。检索摘录不作为正式评分的完整输入。接口未注册时仅保留草稿并说明未开放；模型服务不可用时保留真实失败，不生成假摘录。

A1骨架区分执行失败和业务无法判断、事实未知和false、处理确认和风险解决；风险暂缓仍保留，关闭检测后已有关键项不消失。单条决定使用对象ETag，事实变更使用事实集头ETag，规则补漏使用规则集ETag。已接入本批actual ReviewStateView／ReviewPage／ReviewManifest：新浏览器从服务器恢复准备、阻断、过期、运行及取消中状态；完成后自动接真实轮次，不出现第二次开始。历史轮次分页读取，旧受检稿只由冻结manifest确定，不用当前正文指针代替。处理页结合服务器准备／评审operation与本浏览器受理记录，仍不宣称所有任务历史均可查。纯下一步定位在存在阻断时仍可打开修复对象，实际命令继续独立校验。旧live尚未注册actual接口时显示服务版本未就绪，保留资料和输入。准备请求可使用实际ReviewState强ETag取消；已冻结轮次转处理记录取消。当前A1.2开放规则/事实/问题的单条决定、规则补漏与显式选中pending批量确认；集合强ETag、基准规则包与核对理由共同提交，批量上限从实际schema生成（本候选为100，目标500待后端下批修正）。事实来源变化时保留旧决定但显示需重核。效力影响、事实补替撤回和A1.3仍按实际操作门控。上述业务运行效果仍待相应独立验收。

组件测试使用明确的测试响应，覆盖登录失败、会话过期不重放、网络故障、部分入库、412恢复、响应丢失后的幂等键复用及解析缺口／物理页。A1/RAG/A2组件使用明确的契约形状夹具，验证覆盖和空/失败/来源变化等状态；其中尚未注册的操作只验证机制，不代表部署已支持。字节传输测试验证同源认证与外域隔离。开发自查结果见 `qa-previews/selfcheck-result.json`：真实浏览器／API／S3／Kafka与合成三页PDF，检查真实canvas、空白页、解析缺口、390px及刷新接续。它与独立测试证据分开；单元测试不代表真实解析质量、模型效果或业务验收。

桌面与390px布局支持键盘、可见焦点、持续错误文字和按用途命名的下载入口。手机资料行使用紧凑卡片，原件入口与解析范围保持可见；项目列表只在表格容器内横向滚动，页面本身不应横向溢出。

## 章节编制与固定版本（候选04）

`/bids/:id/authoring?draft=:draftId` 是可选工作面，保留直接上传PDF的主要路径。草稿列表、章节、格式能力、来源投影、历史元数据和构建分页均读取实际API。当前支持闭合的ProseMirror文字/标题/列表及粗斜体；稳定节点ID在格式切换和拆分时保持可追溯。图片、表格及外部Word无损导入未开放。粘贴按纯文字接收，遇图片/表格明确拒绝并保留原稿。

自动保存防抖800ms并串行等待服务端ACK；保存中继续编辑进入下一次保存。导航、切章、构建先排空保存。失响应保留精确正文/幂等键/If-Match，刷新后明确恢复先重放原命令，再保存新编辑。412保留本地和当前服务器稿，只能明确合并或放弃本地。会话内本地内容按成员/项目/草稿/章节隔离；本地缓存不算正式版本，退出时清理。当前成员的最近草稿与章节会在真实列表仍包含该身份时恢复。

章节要求与来源的关联不表示正文满足。引用只接受服务器`authoring-reference`投影，核对项目、证据和文件版本，不推算内部来源编号。手动段落替换先保存，再按稳定节点及原内容摘要获取真实before/after预览，明确应用后追加修订；编辑使旧预览失效。此手动操作不调用模型，应用也不解决风险。章节历史显示真实元数据；当前实际契约缺少单修订正文GET，所以不提供盲恢复。客户端保留能力门控，端点落地并重生类型后才开放正文比较与恢复。

构建等待保存ACK后固定草稿修订，使用内置A4版式，当前仅`follow_up=none`。不会自动把输出变成受检正文或开始评审。受理失响应跨刷新复用原修订与幂等键。服务器BuildPage跨浏览器恢复任务并分页；Word与PDF分别展示成功/失败与缺口，成功文件通过真实授权下载并保留用途文件名，PDF复用原页查看。后续编辑不改变既有快照。开发环境的转换隔离未验收缺口持续以中文说明，不能据本地生成成功宣称生产转换隔离或完整交付通过。

## 实时进度与档案研究

项目使用同源Cookie认证fetch事件流，按实际stream/seq去重、节流重新读取业务快照，不把事件payload当完整对象；空revision仍触发更新。断开携最后游标续接，410先重读再清游标，401停止并保留正文等待登录。服务不可用继续原轮询。浏览器走查请用`domcontentloaded`及具体界面/ACK等待，长期连接下`networkidle`不能作为页面完成条件。

`/history`提供实际档案查询、实交/成绩数量与所属项目入口；项目`/outcomes`区分当前与更正历史、技术分/综合分/未知、真实零分和核验冲突，并保留来源取件。当前不让用户填内部提交UUID，未接上可发现提交身份前不假装可登记成绩。

`/research`读取真实能力与样本，保留正式预测/模型发布不可用原因、来源核验配置状态、样本准入和历史标签。来源分组可填写依据后用实际强ETag保存，412保留输入、读取比较并明确采用新基准；不会自动拆分相关组取得评测资格。收费研究执行、数据集划分和正式业务模型发布尚未在本工作面开放，本轮自查未发模型执行请求。手机可用顶部工作区选择器进入档案/研究，项目页签提供横滑提示。
