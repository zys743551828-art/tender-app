# 确切整包核查的六级下一步

`GET /api/v1/bids/{bid_id}/package-next-actions/{run_id}?expected_input_digest=<SHA256>` 需要有效会话、明确的原运行和不可变输入摘要。只读响应为`package-next-actions/1`，不选择最新报告、不补单稿指针、不自动重试或执行。重复／未知参数拒绝；错误输入摘要412，跨项目／缺失原运行404，API之外的owner／Worker角色403。响应按Cookie隔离且不缓存。

读取复用已验证的确切工作上下文解析器：在同一个非owner REPEATABLE READ只读快照中加载包／要求清单／冻结和准备输入／依赖计划、原结果与当前人工头，重建全部矩阵定义及聚合；观察身份、包头、来源、事实和方法。没有对象原件或模型网络IO，本次不重新授予原字节或新用途资格。方法摘要包含排序器、封闭协议、原生读取、观察和确认读取实现；basis摘要另绑定当前人工头、规则确认观察、生命周期和明确的按原文接受设置。观察时间单独显示，不混入basis摘要。

六级顺序如下，动作只定位到已明确选择的记录或相应工作面：

1. 生命周期、依据变化或不能核验：历史计数可另列，当前数量保持未知。
2. 失败、处理中及本轮无法判断／覆盖缺口：不把未完成填成0。
3. 已选范围的否决／强制要求不符、未找到或无法判断。
4. 当前关键规则仍待确认；按原文接受的明确设置只抑制此确认提示，不清除机器风险。
5. 已选评分条款和改稿依据；当前范围核查不产生正式预测分。
6. 普通建议及整包未覆盖范围检查；不提供“已可提交”的正向动作。

每条要求只归到当前最高优先的动作，主要动作及其余动作不重复定位同一条。剩余关键问题为机器关键问题与当前待确认关键规则的去重并集，排除主要动作已定位的要求；其他建议同样去重。计数仅属于所选已声明范围，绝不等于整包风险、清单完整性或提交资格。人工“确认原判断”“不采用原判断”“需要复查”均不改变机器原判定，也不自动解决风险。

当前关键规则确认按明确规则ID批量读取直接头及已有沿用记录，验证头与记录对象一致，不使用旧报告中的确认状态冒充当前。缺少可核验的当前原生确认时保持未知；明确按原文接受时跳过确认提示。当前规则内容与冻结定义不一致时标记依据变化。上述读取不改变原结果、人工历史或原始冻结校验值。

界面在明确选择的整包核查阶段展示一项主要动作和折叠数量，依据变化按钮展示本次响应中的变化，不打开旧观察冒充当前。失败、串运行、串输入／结果、资格转绿、重复要求或伪造历史总数均不显示旧建议。列表无明确核查选择时仍只显示目录摘要，不从某个最新报告取得风险数字。

直接整包报告复用同一读取和卡片，客户端绑定来自已通过原生验证的所选运行，不构造工作上下文或读取最新报告。除全部输入／方法／结果身份外，动作要求必须属于原矩阵，历史关键问题与建议分别对应原矩阵中的种类及未满足状态，不允许在总数不变时将关键问题移入建议。结果尚未取回时数量未知；结果到达后以明确结果摘要重新读取动作。

项目宿主提供有项目范围的导航，规则和确切包／修订／清单使用已有离开保护。原报告按钮只定位同一页面上的本轮原记录；当前动作重读失败时隐藏动作与数量，已经验证的不可变原报告继续显示。未取得相同项目的导航时不自动拼接全局跳转。
