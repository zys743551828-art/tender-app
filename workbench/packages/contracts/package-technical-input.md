# 完整图文材料的冻结绑定

`package-technical-input-projection/2`仅由owned控制器从同次冻结状态投影，不是公开请求体。调用者独立提供预期投影与当前输入方法摘要；任意JSON自算摘要不授予来源或执行权威。冻结绑定继承scope／输入／完整identity／规则集／判断方法／provider profile／独立核验／文档集合／业务时点的准确摘要，构造器不回填时点，不将声明当作权限。

投影必须保留招标依据和本方材料两种角色的全部已选文档，逐文档固定原件SHA／字节数、解析ID／摘要、物理页数和资产回执。资产映射不得缺文档、混解析或换原件；核验所有页、裁片和PNG字节，精确绑定证据的页图SHA与尺寸、原文SHA、文档、解析及章节页段。规则逐字引文必须来自authority文档，必需范围根节点必须来自target文档；不能从本方自述冒招标条款。

章节是有界无环父树，子章节页段包含在父范围内；跨节引用按显式关系传递展开，引用循环用已访问集合终止。每规则保留根节点、全部后代和传递关联范围，按冻结顺序输出。实际语义输入同时绑定全部冻结文档、每张整页／裁片和所有证据块；范围映射不用于top-k、删页或压缩正文。空白图页可保留无文字，不把OCR缺字补成不存在的文字。元数据的`all_projected_material_retained`只证明当前外部投影保留，不证明投影已经完整覆盖业务必要内容。

`package-technical-input/2`由[封闭Schema](package_technical_input.py)定义，返回材料、页与裁片、原文目录、逐规则范围及语义摘要和精确资产字节。全材料摘要只算一次，各规则绑定同一摘要、来源投影、当前方法和原规则；后续供应商适配器必须实际发送完整材料，不能仅发送摘要。规则请求的序列化／图像内嵌上界、token上界和费用尚须独立profile核验，本构造器不生成HTTP请求或费用承诺。

当前上限为32文档、256页、384图、总1.28亿像素、64MiB资产、2MiB原文、4MiB投影及8MiB结果元数据，单文档同时受资产协议约束。任何超限直接失败，不返回部分输入，不截断、不降采样。输入／输出均为闭包，不接官方标签、历史导出、聊天、前次判断或资格开关字段；原文的真实来源和用途仍必须由独立最小权限适配器保证，Schema不能判断文本中是否偷带标签。

处理器无DB／存储／provider／环境端口，不重读原PDF，不证明原件历史存在、实际可读性、完整必要范围或硬隔离。输入权威、原字节重核、可读性、历史证明、供应商payload、执行／正式预测／训练资格始终false。后续正式执行仍需独立核验回执、当前来源复查、受限资产Worker、原生持久化和费用／租约接线；旧scope、解析、报告与/1机制均不改写。

## 核验上下文与最终输入的单向绑定

`package-technical-context-projection/2`在独立核验之前冻结，绑定字段明确没有`input_verification_digest`，也不接受占位字段。`build_verification_context`执行与最终输入相同的完整材料、规则、页图和章节闭包检查，输出`package-technical-verification-context/2`及私有资产快照；该类型不能直接交给图文序列化器。

独立原生权威后续返回`package-technical-verification-binding/2`，含核验记录ID、真实回执摘要、确切context与方法摘要。`bind_input`要求调用者独立提供context和原生binding记录的预期摘要，重建context并重核资产，随后才把真实回执摘要放入最终输入。全零回执摘要拒绝。context不依赖回执，回执指向context，最终输入指向回执与全部材料；不同回执产生不同最终输入，但不会改变已冻结context或旧报告。

本函数只绑定外部独立返回的原生记录，不验证签名、发行方资格、内容真实、必要范围或当前来源，也不把合成binding当作已经安装的权威。正式入口必须由独立最小权限适配器取得实际记录及预期摘要，不能从用户请求接收JSON和自算预期值。纯材料构造器仍只授一致性而非执行资格。方法身份包含源码和契约，加入context流程产生新的输入及依赖它的序列化方法摘要；已存旧输入、manifest、回执和报告字节不更新、不补填。
