# 项目整包目录摘要

`GET /api/v1/project-work-summaries?bid_id=<UUID>&bid_id=<UUID>` 需要有效会话，每批1—20个不同项目，输出顺序与请求一致。缺失项目或损坏的包head导致整批拒绝，不静默返回部分结果或把失败变成0。读取在同一个REPEATABLE READ只读事务中完成，数据库语句限时3秒，不创建命令、任务或模型调用，不改变原项目ETag／CAS。

封闭协议`project-work-summary/1`包含观察时间、生命周期登记状态、各类已登记包数量、当前head修订的文件成员数量及解析身份未冻结数量。成员数按包head计数，相同原件出现在两个包中算两个成员；不把所有历史修订重复计入，也不以最新解析替换当时明确选择。目录中的包数量为0是已读到的登记数量，风险与预测未核对时始终是null，不得转成0。

`action_scope=package_directory`表示这只是资料包定位动作。已结束／归档项目指向稿件阶段历史；缺招标依据包或投标包时提示登记；存在未冻结解析身份时提示核对；其余情况下仍要求用户选择确切包修订。多个包、多个清单或多个核查运行不自动选择最新一项。当前段不提供六级风险动作的完整排序，不把登记数量或解析身份计数当作风险、清单完整性、正式评分或标准提交资格；三个资格字段保持false，风险计数和预测分保持null。

列表和项目概览使用同一后端摘要及前端读取器。读取器每批20项、最多两个同时进行的请求；不同批次各有自己的观察时间，不冒全目录原子快照。切换项目、刷新或服务器事件会使旧请求失效，晚到结果不覆盖新摘要；失败或身份不一致时隐藏此前摘要和动作并提供重读，不回退使用旧单稿提示。没有定时清空摘要造成闪烁；已有服务器变更事件和明确重读可更新。导航只打开工作面，不自动确认、冻结、启动核查或产生费用。
