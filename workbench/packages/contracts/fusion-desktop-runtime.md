# Windows 本机完整 Compose 传输

`deploy.fusion_desktop` 将完整运行时的 Linux 私有目录映射为专用 Docker named volumes，避免 Windows bind mount 无法提供 POSIX 600／700 的权限语义。它复用原配置、全新初始化、角色画像校验和业务入口，不放宽私有文件检查，不承接现有业务库。

公开目录只能位于工作台 `.local/full-desktop/` 的一个直接子目录。`prepare` 仅创建新目录；调用者必须明确提供固定 digest 的 Python／Web 镜像、独立名称和 IPv4 回环来源。主机保存公开请求、清单、计划和摘要，不保存口令。`up` 依次完成 configure、基础服务、init、publish、独立业务角色。默认不启用付费模型或自动任务。入口默认 5189，原 5188 预览保留。

configure 在 Linux 卷内部生成强随机初始口令，不修改已有口令策略；owner 口令以 PostgreSQL 要求的 `owner_password` 文件名只交给数据库服务。init 独占初始化凭据及状态；publish 只将五种独立角色画像复制到各自卷，目录 700、画像 600、属主 65532。业务服务以 65532 运行，只读挂载自身画像，不挂载 owner、其他角色或 Docker socket；API 状态有独立卷。源码为开发环境只读挂载，不等于不可变生产镜像。

首次初始化空状态卷时设置 700，已有非空状态卷权限不符时拒绝而不修复。publish 另外准备一个独立的验收登录卷，仅包含本候选的强随机管理员登录和公开身份，不含 owner、Worker 或其他服务凭据。显式 `verify` 才以 checks profile 启动 65532 用户的验收服务：只读 API 画像与验收登录卷，通过真实 nginx HTTP、存储、Kafka 和 Worker 使用合成 PDF。要求全新空项目库，测试后保留明确标记的合成项目及证据；再次验收使用全新候选。验收脚本不得输出口令、会话、票据、原件或连接串；不启用模型，不授真实评分资格。验收服务不暴露主机端口。

运行计划冻结实际输入。Linux 公共 SQL 路径使用 `/`；主机核对完全相同的有序路径和摘要，再以临时副本适配本机路径分隔符，不修改冻结原件。源码、依赖、前端或部署策略改变后应停止旧候选并新建候选，不修复旧身份。`status`／`stop` 验证保存的传输摘要和实例标签，源码变化不阻碍停止；不删除数据卷。

完整运行时固定使用 SeaweedFS 4.48 的内容 digest。实际二进制支持 `-iam=false`、两个额外协议端口置 0、禁止上传时自动创建桶和禁止非空桶删除；结构检查拒绝这些参数被移除。原 3.97 digest 不支持该配置，不能作为本配置已通过验证的镜像。存储服务不暴露主机端口，正常 API／Worker 使用独立的指定桶凭据。镜像参数兼容通过不代表桶隔离、文件链路、容量或浏览器视觉已验收，这些必须记录实际结果。

纯检查入口为 `deploy/fusion.ps1 -Action checks -Suite desktop-pure`，归入既有 `tender-fusion` 检查组。完整环境以 `tender-fusion-full-<实例前缀>` 单独成组。所有部署失败须保留阶段、原因和证据，不把容器创建或 queued 当作服务健康。
