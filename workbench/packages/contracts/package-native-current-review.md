# 原生材料与独立审核的当前联合核对

通过六个实际独立、初始空闲purpose连接，固定读取原生登记和独立审核回执；审核当前状态先查一次，随后重读私有证据、重新GET全部当前原件并重核准确解析／来源图／范围／定位及完整报告，最后再次核独立审核和固定登记。HTTP期间连接不持有事务，调用方事务拒绝且不回滚调用方工作。

登记／context／scope及审核record／reference摘要由调用方独立固定。引用须与准确登记、存储、完整报告及审核清单一致；审核前后实际回执相同、当前有效且head修订保持。核验期间撤销或重新启用均拒绝，旧事实、原context／manifest、原报告和登记观察不改，保存单独的当前恢复及前后审核观察。

结果NativeCurrentReview区分要求改动、无法完整核验、合成审核与配置当前审核确认；这些状态只描述当前原生事实与配置主体声明。必要范围／原生binding／输入／执行、真实人工阅读、可信实时派生、历史存在、原子快照及send lease均false。单次恢复内有原件前后核对，联合流程不保证各独立事务原子性，不能凭这些观察直接发送或正式评分。

过程只调用已有读取端口，不新增DDL／授权／BASE／HTTP／UI，不依赖本机POSIX私有CAS。六类用途不能互相替代，存储写者不能充读者，审核签署者不能自证；没有latest／时间推算历史身份。下一层资格须核可信处理程序／真实审核政策及当前状态，执行另需原生费用和lease屏障。
