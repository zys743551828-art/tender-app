# 完整输入的当前证据续验

原生核验的程序事实有短有效期。到期后，旧封存及旧报价的历史事实保持，原当前资格为false。不能把这些记录改时，也不能只换核验UUID重建输入而使同一任务的input_digest／请求内容变化。

续验接收原封存／报价、一个新原生独立核验及配置profile的准确ID／摘要。新核验来自已持久命令的受控程序重新读取全部原件、实际重算页图裁片、复核准确解析／范围及同一完整报告，再由原生独立政策重新核准。新旧核验必须同bid／scope／context／方法／完整报告／政策及修订／原生登记／审核引用；旧封存／私有存储、原价格政策／修订、各主体LOGIN／OID及当前purpose必须有效。不能用其他scope或新版context借给旧输入续验。

专用续验LOGIN／OID与报价、封存、核验和程序分开；初始化者固定续验主体、准确报价政策、origin、接口及实际SQL指纹、数据库身份和有效期，head修订另存。共同锁及全部相关head／来源行锁内复核后，追加原生续验UUID／时间／主体，明确保留原admission_verification和新current_verification两个身份。

逻辑续验command必须是新程序已持久的逻辑命令，不能任意换nonce产生新调用意图。同command准确重放，其他引用冲突；未知结果可重开。记录保留原material_input_digest／quote_digest／context，不重建旧MaterialInput/3引用，不改原manifest或历史报告。新旧请求字节摘要与语义摘要须在验证中逐条核对，不能把尚未存在的模型调用或发送记录当作已验证。

read返回固定续验及当前profile／新核验／原封存配置／价格有效性，过期／撤销仍使当前观察失效，不能把历史续验当发送lease。软件续验与原生绑定不是资金预留、账户合同、精确token可装入、请求体预检或执行资格；所有这些授予仍false。合成不授生产资格。后续原生任务和资金／发送须引用准确续验并在自身事务中再核，不信任外传JSON布尔。不自动选择latest，也不按时间推算历史身份。

仅全新独立检查库可选安装，不进入BASE、正常业务数据库、公开HTTP或前端。
