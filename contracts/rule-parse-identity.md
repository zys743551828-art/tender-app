# 规则提取的解析来源

规则提取入队使用 `rules-input-v2`：任务 `input_json` 保存 `file_version_ids` 和 `parse_inputs`，后者结构与 [input-v2 快照](snapshot-parse-identity.md)相同。排序后完整任务输入参与 `input_sha256` 和任务幂等键；相同逻辑请求在解析或证据集合变化后取得新任务身份。

执行前核对冻结集合仍为当前值，变化则失败 `rules_inputs_stale`，不调用模型。模型只能看到被冻结且满足原有文字／已核验条件的证据。任务没有冻结字段时失败 `rules_parse_identity_unknown`，不根据当前解析补写旧任务。提取产物保留 `parse_inputs`、任务输入校验值、原有提示词／模型、规则与丢弃原因。

结果入库在项目锁内复核当前文件、解析和证据集合。提取期间来源变化时，任务产物保留供追溯，不建立当前规则包；流水线按实际最新输入准备新提取。任务成功表示处理产物已保存，不保证该产物仍能作为当前规则使用。

迁移 [rule-parse-identity.sql](rule-parse-identity.sql) 给规则包增加只追加的 `parse_inputs_json`。人工条件核实、补遗影响决定和冻结后的规则更正副本继承该来源。旧包保持 null，不能按文件时间或证据时间推测回填。

`RuleSet.source_parse_state` 为 `current`、`stale` 或 `legacy_unfrozen`。后两者保留条款、引用和历史决定供查看，但普通规则确认、批量确认、投标条件核实、补遗影响决定、新快照与新提交均须先使用当前来源：未知来源返回 409 `rule_parse_identity_unknown`，已知但过期返回 409 `rules_parse_stale`。原有版本检查和输入文件检查仍可更早拒绝请求。

来源过期或未冻结时，已有成功提取任务不能使页面永久显示处理中；没有当前活动提取任务则提供开始入口。依据页显示说明与“重新提取并评审”，按原会话、CSRF、幂等和正式评审接口执行。项目 AI 不为过期规则提供批量确认卡，确认卡指纹纳入项目身份、解析 ID 与每次解析的证据数量。

同一文件版本的解析／证据变化时，不把之前的人工决定与补遗效力决定自动继承到新提取包。新增／替换文件版本继续沿用既有同条文匹配规则，但共同保留的文件版本必须保持相同解析身份；否则新包重新核对。旧规则包与旧评审输入保持原值。

此契约与快照冻结共同保护后续 OCR／表格核验。候选采用／订正接口与界面、扫描表格结构、跨页关联及真实业务质量另行验收。
