# Word 原稿与实际评审 PDF

Word、实际 PDF、二者的对应关系和采用决定分别保存。Word 版本之间使用原有 `version_of_file_id`；Word 与 PDF 不能互作文件版本。受控转换或用户补交的 PDF 都是独立逻辑文件，字节相同可以共享内容寻址产物，原件和历史记录不被覆盖。关联 PDF 的替换从原稿处进行，不能直接延长关联 PDF 的版本链。

## 上传和查询

原有上传接口增加可选 `source_word_version_id`。传入它表示用户声明“此 PDF 对应这版 Word”，不是系统核实内容一致。必须同项目、同用途、源为当前 Word，且不同时传 `version_of_file_id`；补交类型必须是 PDF，完成时核对实际 PDF 头及原有大小／SHA256。补交 PDF 保留独立取得时间。

若源 Word 在上传开始后更新，完成时仍保存此 PDF 及其与旧稿的关系，但不采用为当前稿。一次上传完成的重放沿用现有幂等结果，不再追加关系。

文件清单在 Word 上附加 `word`：当前性、最近转换状态、失败码、已采用 PDF 和候选列表；每个候选包含关系 ID、PDF 版本 ID、方法与待核实缺口。实际 PDF 附加 `source_word_version_id`。材料页把它们展示在对应原稿下，历史原稿只读。

## 转换与采用

`parse` worker 读取并核对原件摘要后，将 Word 送入[隔离转换队列](word-conversion.md)。失败回执在任务失败事务中追加；成功生成独立 PDF 后，在同一租约保护事务中追加文件、转换回执、关系及 PDF 解析任务。没有生成 PDF 时不写成功解析证据。

只在保守检查无缺口、原稿仍为当前且尚无采用决定时自动采用。复杂布局、文字或字体缺口的 PDF 保持待核实；晚到转换不覆盖已经采用的人工 PDF，也不替代新稿。旧 `.doc`、动态域、外部关系等不支持输入可在原稿处只补交 PDF。

- `POST /files/{version_id}/word:adopt`：传 `link_id`、非空 `reason`、`reviewed_pdf=true`。核对项目、Word 当前性、候选关系和 PDF 当前性后追加采用及审计。旧稿或旧 PDF 返回 409，未确认核对返回 422。
- `POST /files/{version_id}/word:retry`：空 JSON；必须已配置方法指纹、Word 仍为当前且该稿没有未结束的解析任务。只重试 Word 转换，不冻结输入或调用模型。方法未启用为 503，重复运行或旧稿为 409。

两者使用会话、CSRF 和幂等键。API 只读取方法配置，队列只挂载给解析 worker；没有 Docker socket、转换服务端口或额外业务凭据。

## 当前材料和历史输入

流水线、招标规则来源、当前检索、补遗影响和快照使用同一套当前材料解析。Word 按原稿取得时间排序，只有已采用且仍为最新的实际 PDF 能代表它。正文只取最近原稿；新 Word 没有可采用 PDF 时不会退回上一版 PDF。关联 PDF 自身的生成或补交时间不改变原稿之间的顺序。

流水线 `word_pdf_required=true` 时，首要动作指向材料页核对或补交此稿，避免把人工核对显示成持续运行或催促重跑评审。未采用和未解析输入不能进入新快照。

快照清单及数据库 `word_sources_json` 同时冻结原稿、实际 PDF、两者摘要、关系、采用决定与受控方法指纹；对外 `word_sources` 读取这份冻结记录。Word 原稿不作为已解析 PDF 加入评分证据。历史快照继续读取自身材料，后续改稿不改写它。

截止校验仅对受控转换沿用 Word 原稿取得时间；用户补交按 PDF 实际取得时间，不因声称对应旧稿而倒签。正式提交仍绑定实际 PDF 和有效评审快照，原稿对应声明不代表 Word 合格。

表结构以 [word-materials.sql](word-materials.sql) 为准，由 0004 迁移添加；三类回执、关系和采用表只追加，跨项目外键约束生效。部署前先备份，回退依赖备份恢复。

范围外：真实标书复杂版式准确率、扫描表格／图形语义质量和多 worker 容量；进程崩溃后遗留队列输入的自动回收未验收。共享卷是临时传输层，正式原件和历史来源由业务档案保存。
