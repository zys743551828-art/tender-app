# 补遗的有据效力决定

规则包的 `effectivity_json` 由增量迁移 0003 增加，契约见 [rule-effectivity.sql](rule-effectivity.sql)。旧包、证据与原件不改写；每次决定创建新规则包，保存范围、理由与审计。不会因上传顺序自动推断替代。

范围处理包括 `whole_replace`（整份替代）、`partial_replace`（仅替代选中条款）、`defer`（关系待核实）；另有 `retain` 供核实后保留或更正选择。整份替代由服务器列出原资料的全部对应条款，不能夹带局部选择；同时引用多份原件的规则保持待核实。局部替代只结束明确选中的规则；未选规则及补遗的新规则继续保留。待核实不自动当作通过，阻断新快照；核实保留可以清除待核实或结束状态。

`POST /projects/{id}/rules/effectivity:preview` 只读预览，接收当前规则版本、原资料／补遗版本、动作和所选规则 ID。返回受影响规则、混合来源规则、最多五个关键词相关的当前正文章节及缺口；章节引用附物理页。它是相关性提示，未命中不证明没有影响，也不声称范围完整。

`GET /projects/{id}/rules/source-evidence/{version}` 列出当前招标／补遗的可用原文片段，支持 query 关键词，最多 30 条。只含原生 text 或已核验候选，不把未核验 OCR 当作效力依据。

`POST /projects/{id}/rules/effectivity:decide` 接收预览字段、`scope_basis`（补遗证据 ID 与逐字范围说明）及非空理由。要求会话、CSRF、幂等键；项目锁内验证当前规则版本和源资料版本未变。旧、新资料必须不同且属于当前规则包，新资料用途必须 supplement，选中规则必须实际引用原资料。非 defer 动作必须附补遗原文依据。摘录必须逐字来自所选补遗的可用证据；整份替代遇到原段落的“其余不变／仅修改”等明确局部说明会拒绝，不能仅摘掉限定语绕过。

提交前从对象存储读取两份原件，复核字节数与 SHA-256。缺失／网络故障返回 503，不产生部分新包；字节不符返回 409。验证通过后，追加新规则包、复制条款与已有审核，记录 `source.effectivity_decided` 审计；旧包与旧报告保持。重复幂等请求返回原结果。

效力身份包含性质、条文、条件、例外、规范化分值及精确证据 ID。重新提取相同要求和证据可沿用；要求或证据改变后旧终止决定不自动套用。`Rule.source_status` 返回 active／superseded／needs_confirmation；实际规则核对与评分排除非 active 条款。普通规则确认或“全部按原文确认”不能覆盖效力决定。

项目流水线用 `input_verification_required` 声明投标条件或条款效力仍待核实；首要动作 `verify_sources` 指向依据页，界面不反复提供无效重试。原件查询和检索保留原文，在 `EvidenceRef.effectivity_notes` 标出当前具体要求的效力，同时声明同页其他要求不因此失效；旧报告引用仍是原输入，这些提示明确指当前规则版本。

界面先预览范围，再选择补遗原文和填写理由。打开核实框时固定所见规则版本，后台刷新不能默默升级提交版本；选择变化后旧预览失效。确认创建新规则版本，后续评审使用新包。

边界：本模块提供人工有据的范围决定，不自动发现和解决全部补遗语义冲突。条件满分／报价歧义另见 [term-conflicts.md](term-conflicts.md)。正文相关章节使用关键词；范围残留辅助检测仍读取原件文本，未实现完整的条款级有效范围求解。复杂条件例外、跨页图形、自动影响完整性和真实工程准确率尚需独立验证。
